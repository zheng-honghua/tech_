## 总体调用关系

```text
相机/回放
  ├─ RGBFrame ───────────────> VisionPipeline ─────> RGBDevelopmentPipeline
  └─ RGBDFrame ─> 标定/ROI ─> VisionPipeline3D ───> VisionResult3D
                         │          │
                         │          ├─ 深度实例与点云
                         │          ├─ 颜色与多姿态形状模型
                         │          ├─ 可见面/融合棱线特征
                         │          └─ 吸附面与三维位姿
                         │
                         └─────────────────────────> health

VisionResult3D + health
  └─ VisionService3D + MotionInterlock ─> JSON/TCP 控制端
```

RGB 与 RGB-D 共用颜色分类和一部分轮廓工具，但安全语义不同：RGB-only 永远是 `DEPTH_REQUIRED`；RGB-D 也只有 `PICKABLE` 且 `selected=true` 才可能进入控制端。标注颜色和字段见 [RGB-D 结果颜色与字段说明](RGB-D结果颜色与字段说明.md)。

## 1. 入口、配置与公共数据结构

### [`__init__.py`](../../src/sorting_vision/__init__.py)

包初始化文件。当前不承担业务逻辑，也不集中重导出类。集成代码应从具体模块导入，避免依赖隐式包级 API。

### [`cli.py`](../../src/sorting_vision/cli.py)

统一命令行入口，负责参数解析、读取配置、创建相机/模型/流水线并保存输出。安装项目后可以使用：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli --help
```

所有命令共享全局 `--config`，必须写在子命令前：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli `
  --config config/d435if-initial.yaml `
  rgbd-detect --help
```

模块内部 `_run_*`、`_write_*` 函数是 CLI 实现细节，不应作为稳定第三方 API。命令清单见[第10节](#10-cli-命令索引)，测试见 [`test_live_camera.py`](../../tests/test_live_camera.py)、[`test_single_image.py`](../../tests/test_single_image.py) 等各功能测试。

### [`config.py`](../../src/sorting_vision/config.py)

把 YAML 配置加载为带类型的 dataclass：`TrayConfig`、`SegmentationConfig`、`ClassificationConfig`、`SelectionConfig`、`RGBDConfig`、`GraspConfig`、`NetworkConfig`、`CameraConfig` 和 `MotionInterlockConfig`，最终组合为 `VisionConfig`。

常用入口：

```python
from sorting_vision.config import load_config

config = load_config("config/d435if-initial.yaml")
print(config.rgbd.processing_scale)
print(config.grasp.cup_diameter_mm)
```

省略路径时读取 [`config/default.yaml`](../../config/default.yaml)。现场调参应新建 YAML，不要把相机专用数值写死在算法中。测试主要分布在对应流水线测试中。

### [`types.py`](../../src/sorting_vision/types.py)

定义跨模块传递的数据协议：

- `DetectionStatus`：`PICKABLE`、`UNCERTAIN`、`OCCLUDED`、`DEPTH_INVALID`、`NO_GRASP_SURFACE`、`DEPTH_REQUIRED`。
- `Point2D`、`Point3D`、`Quaternion`、`Pose3D`：位置与姿态。
- `GraspInfo`：吸盘直径、平面拟合误差、边缘余量、有效深度率和评分。
- `Confidence`、`Confidence3D`：各阶段置信度及几何平均综合分数。
- `VisionResult`：旧 RGB 二维结果。
- `VisionResult3D`：协议 v2 的 RGB-D 结果。
- `SegmentedObject`：二维分割候选。

控制端应调用 `VisionResult3D.to_dict()` 获得协议字段，不要直接序列化 dataclass 内部属性。协议示例见根 [README 的结果协议 v2](../../README.md#结果协议v2)。

## 2. 相机、帧与标定

### [`camera.py`](../../src/sorting_vision/camera.py)

封装图像来源与 RGB-D 文件读写：

- `RGBFrame`：单目彩色帧。
- `ColorSource` / `RGBDSource`：相机适配器协议。
- `OpenCVCameraSource`：Windows/Linux UVC 摄像头。
- `RealSenseSource`：通用 RealSense 彩色与深度流、对齐、内参、深度比例和时间戳。
- `RealSenseD435IFSource`：D435if 设备名和帧前缀便捷类。
- `RealSenseD415Source`：保留给历史调用的 D415 兼容类。
- `FileRGBDSource`：按文件夹回放已有帧，可选择循环。
- `save_rgbd_frame()` / `load_rgbd_frame()`：读写 `color.png`、`depth.npy`、`metadata.json`。

RealSense 导入保持懒加载；只有使用 D435if/其他 RealSense 时才需要安装 `.[realsense]`。修改相机行为运行 [`test_live_camera.py`](../../tests/test_live_camera.py) 和 [`test_rgbd.py`](../../tests/test_rgbd.py)。

### [`rgbd.py`](../../src/sorting_vision/rgbd.py)

定义 RGB-D 数学基础：

- `CameraIntrinsics`：宽高、焦距、主点和深度比例。
- `RGBDFrame`：对齐后的彩色图、原始深度、内参和双路时间戳。
- `Plane`：平面法向、偏移和点到平面距离。
- `RGBDCalibration`：内参、相机到机器人 4×4 变换、托盘平面与可选托盘参考多边形。
- `backproject_pixels()`、`project_points()`、`depth_to_points()`：像素、深度与点云互换。
- `fit_plane_svd()` / `fit_plane_ransac()`：平面拟合。
- `resize_rgbd_frame()`：同步缩放 RGB、深度与内参。

深度数组通过 `RGBDFrame.depth_mm` 转成毫米；不要直接把 `depth.npy` 当毫米使用。测试见 [`test_rgbd.py`](../../tests/test_rgbd.py)。

### [`calibration.py`](../../src/sorting_vision/calibration.py)

保留旧 RGB 二维透视标定 `PerspectiveCalibration`。它把四角区域矫正为俯视图，并提供像素到毫米的平面换算。只适用于二维开发链路，不能替代 RGB-D 的三维外参。

命令：`calibrate --point ...`。测试见 [`test_calibration.py`](../../tests/test_calibration.py)。

## 3. RGB 二维开发链路

### [`pipeline.py`](../../src/sorting_vision/pipeline.py)

`VisionPipeline` 是旧二维总流水线：透视矫正、前景分割、颜色/形状分类、二维中心和角度估计、候选排序、连续帧稳定与标注。它返回 `VisionResult`。

适用场景：UVC 预览、RGB 算法开发、旧接口兼容。它不能证明深度、吸附面或三维位姿有效。

主要入口：`process()`、`rectify_frame()`、`annotate()`、`reset_tracking()`。测试见 [`test_pipeline.py`](../../tests/test_pipeline.py)。

### [`rgb_development.py`](../../src/sorting_vision/rgb_development.py)

`RGBDevelopmentPipeline` 把 `VisionPipeline` 包装成与三维服务相近的接口，便于 `camera-live` 和 `serve` 共用代码。它强制：

- `status=DEPTH_REQUIRED`
- `pose_3d=None`
- `grasp=None`
- `selected=false`

不要删除这层安全降级来“让 RGB 也能抓”。测试见 [`test_rgb_development.py`](../../tests/test_rgb_development.py)。

### [`segmentation.py`](../../src/sorting_vision/segmentation.py)

完成二维托盘图像的前景掩膜、连通域提取、接触区域分水岭拆分、面积/形状过滤和候选间距计算。

公共入口：`foreground_mask()` 和 `segment_objects()`。也可通过实现 `InstanceSegmenter.segment()` 接入新的二维实例分割器。测试见 [`test_segmentation.py`](../../tests/test_segmentation.py)。

### [`classification.py`](../../src/sorting_vision/classification.py)

包含：

- `LabColorClassifier`：在对象掩膜内按 Lab 色差分类。
- `GeometricShapeClassifier`：基础轮廓规则分类器。
- `HybridShapeClassifier`：统一 OpenCV/CNN 几何模型与规则后备接口。
- `LabelPrediction`：标签、中文名、置信度和特征。

RGB-D 也复用 `LabColorClassifier`，但形状分类走 `classification3d.py`。测试见 [`test_classification.py`](../../tests/test_classification.py)。

### [`pose.py`](../../src/sorting_vision/pose.py)

二维兼容工具：`safe_grasp_point()` 找掩膜内部安全点，`principal_angle_deg()` 计算主方向，`estimate_pose()` 把二维位置映射为旧接口毫米坐标，`masked_crop()` 生成中性背景裁剪。

RGB-D 真正的吸附面和三维姿态由 `grasp3d.py` 计算。

### [`extensions.py`](../../src/sorting_vision/extensions.py)

旧二维流水线的附加分析接口：

- `VisionExtension`：实现 `analyze(image, mask) -> dict`。
- `QRCodeExtension`：对象区域二维码检测。
- `CallableExtension`：把普通函数包装成扩展。

扩展结果只进入 `VisionResult.extensions`，不会自动改变安全状态或三维抓取判定。

## 4. 单图与多物体 RGB 预测

### [`single_image.py`](../../src/sorting_vision/single_image.py)

`GeometryImagePredictor` 面向“一张图片、一个主体”：加载 NPZ/OpenVINO 模型，预处理主体，输出 `SingleImageResult`，并可保存 `result.json`、标注图、裁剪和掩膜。

首选命令：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli predict-image `
  "sample.jpg" --output-dir "output\single-image"
```

空图、多主体、主体出界或模型拒识会得到明确原因。测试见 [`test_single_image.py`](../../tests/test_single_image.py)，教程见[单图预测使用说明](单图预测使用说明.md)。

### [`scene_image.py`](../../src/sorting_vision/scene_image.py)

`GeometryScenePredictor` 面向“一张 RGB 图、多个彼此分离的主体”：先拆出候选，再逐个调用 `GeometryImagePredictor`，返回 `SceneImageResult`，保存整图标注与每个对象的裁剪、掩膜和诊断。

接触或重叠物体可能被合并；该模块不是 RGB-D 抓取流水线。测试见 [`test_scene_image.py`](../../tests/test_scene_image.py)，教程见[多物块场景预测使用说明](多物块场景预测使用说明.md)。

## 5. RGB 几何、棱线与 CNN

### [`geometry_models.py`](../../src/sorting_vision/geometry_models.py)

定义 RGB 几何模型的公共抽象：`GeometryCandidate`、`GeometryPrediction`、`GeometryShapeModel`，以及尚未默认启用的 `EnsembleGeometryModel`。OpenCV 和 OpenVINO 后端通过该协议返回一致的候选、置信度和拒识原因。

### [`geometry_rgb.py`](../../src/sorting_vision/geometry_rgb.py)

轻量 OpenCV RGB 模型的训练、加载、预测和评估中心：

- `load_geometry_samples()`：从“父文件夹即类别”数据集读取样本。
- `preprocess_geometry_object()`：主体选择、裁剪和掩膜标准化。
- `extract_geometry_features()`：按模型版本提取旧轮廓、棱线拓扑或结构拓扑特征。
- `GeometryRGBModel`：拟合、拒识、预测、保存和兼容加载 NPZ。
- `audit_geometry_dataset()`、`train_geometry_model()`、`evaluate_geometry_holdout()`、`compare_geometry_models()`、`export_geometry_results()`：数据审计与实验工具。

当前稳定 RGB 模型使用 edge-topology 中的形态学和色块辅助版本。测试见 [`test_geometry_rgb.py`](../../tests/test_geometry_rgb.py) 和 [`test_geometry_models.py`](../../tests/test_geometry_models.py)。

### [`geometry_edges.py`](../../src/sorting_vision/geometry_edges.py)

提取二维物块内部棱线拓扑：Lab 色块/梯度候选、形态学骨架、线段拟合、共线合并、交点、平行/汇聚关系和可见面几何。主要数据结构为 `EdgeLine`、`EdgeJunction`、`EdgeTopology`。

公共入口：`extract_edge_topology()`、`edge_topology_vector()`、`render_edge_lines()`。这里的二维棱线主要服务 RGB 模型，不等同 RGB-D 真实深度棱。测试见 [`test_geometry_edges.py`](../../tests/test_geometry_edges.py)。

### [`geometry_edge_audit.py`](../../src/sorting_vision/geometry_edge_audit.py)

将带文件夹标签的 RGB 数据批量导出原始线、合并线、交点、色块和拓扑 JSON。公共入口 `audit_geometry_edges()`，CLI 为 `geometry-edge-audit`。它只生成诊断，不训练或替换模型。

### [`geometry_structure.py`](../../src/sorting_vision/geometry_structure.py)

在 `EdgeTopology` 基础上生成更保守的轮廓—线—点结构：拟合外多边形、连接断线、重建交点、吸附端点、删除悬空线和重复线。数据结构为 `StructuralLine`、`StructuralVertex`、`StructuralContour`。

公共入口：`extract_structural_contour()`、`render_structural_contour()`、`structural_contour_vector()`。当前结构模型是实验版本。测试见 [`test_geometry_structure.py`](../../tests/test_geometry_structure.py)。

### [`geometry_structure_audit.py`](../../src/sorting_vision/geometry_structure_audit.py)

批量导出结构线和顶点诊断：

- `audit_geometry_structures()`：有文件夹标签的单物体数据。
- `audit_geometry_scene_structures()`：无标签多物体场景，先分割再逐物体导出。

对应 CLI：`geometry-structure-audit`、`geometry-scene-structure-audit`。

### [`geometry_cnn.py`](../../src/sorting_vision/geometry_cnn.py)

MobileNetV3-Small 训练与 OpenVINO 部署模块：

- `OpenVINOGeometryModel`：加载 OpenVINO 模型并按置信度/间隔拒识。
- `load_geometry_shape_model()`：按 `opencv` 或 `openvino` 返回统一模型接口。
- `train_geometry_cnn()`：去重、分层交叉验证、训练、续训和微调。
- `export_geometry_cnn()`：导出 ONNX、FP32/FP16/INT8 OpenVINO。
- `evaluate_geometry_backend()` / `benchmark_geometry_backend()`：准确率与 P50/P95。

推理安装 `.[cnn]`，训练安装 `.[cnn-train]`。当前 CNN 全部位于 `models/experimental/cnn/`，不得用于机械执行。测试见 [`test_geometry_models.py`](../../tests/test_geometry_models.py)。

## 6. RGB-D 三维识别与抓取

### [`pipeline3d.py`](../../src/sorting_vision/pipeline3d.py)

`VisionPipeline3D` 是推荐主流水线，负责：

1. 校验 RGB-D 尺寸、内参和同步信息。
2. 缩放帧并检测/约束托盘 ROI。
3. 检查托盘有效深度、平面漂移和 RGB-D 同步，生成 `health`。
4. 基于托盘高度分割对象，并用 RGB 轮廓补全显示掩膜。
5. 运行颜色、点云形状、抓取面和位姿分析。
6. 按安全优先级生成状态，从 `PICKABLE` 中选择综合分数最高者。
7. 连续帧稳定后设置 `selected=true`，生成标注图。

主要入口：`process()`、`health()`、`annotate()`、`acknowledge_pick()`、`reset_tracking()`。测试见 [`test_pipeline3d.py`](../../tests/test_pipeline3d.py)。

### [`geometry3d.py`](../../src/sorting_vision/geometry3d.py)

三维分割与局部几何：

- `valid_depth_mask()`：按配置过滤无效/越界深度。
- `height_map_from_plane()`：计算每个像素相对托盘平面的高度。
- `estimate_plane_shift_mm()`：检测当前托盘平面漂移。
- `segment_depth_objects()`：高度前景、RGB 支持、接触拆分、碎片合并和间距。
- `object_point_cloud()`：把一个实例转换成点云。
- `local_surface_plane()`：拟合候选抓取点附近表面。

安全代码必须保留“RGB 掩膜只补显示，点云与抓取仍使用有效深度”的边界。测试见 [`test_geometry3d.py`](../../tests/test_geometry3d.py)。

### [`rgb_instance.py`](../../src/sorting_vision/rgb_instance.py)

`recover_rgb_masks()` 利用颜色连通域恢复被深度孔洞截断的 RGB 可见轮廓。它受托盘 ROI、饱和度、实例归属、重叠率和面积倍率约束。

恢复结果用于颜色和显示裁剪；不会把缺失深度补成点云或吸附面。测试见 [`test_rgb_instance.py`](../../tests/test_rgb_instance.py)。

### [`classification3d.py`](../../src/sorting_vision/classification3d.py)

提供三维形状分类接口：

- `ShapeModel3D`：任何新点云/RGB-D 模型需要实现的 `classify(...)` 协议。
- `PrimitiveShapeClassifier3D`：无训练模型时的规则几何基线。
- `HybridShapeClassifier3D`：优先调用传入模型，并保留有限的几何一致性校验/后备规则。

省略 `--rgbd-shape-model` 会使用规则基线，不会自动加载稳定 v4。测试见 [`test_geometry_models.py`](../../tests/test_geometry_models.py)。

### [`face_topology3d.py`](../../src/sorting_vision/face_topology3d.py)

从对象有效深度内部拟合可见平面和面邻接，数据结构为 `PlanarFace3D`、`FusedEdge3D`、`FaceTopology3D`。公共入口：

- `extract_face_topology()`：RANSAC 平面、法向、面积、误差、邻接、二面角和可选 RGB-D 融合棱线。
- `face_topology_features()`：旧 v2/v3 面拓扑特征。
- `fused_edge_features()`：追加的 9 维融合棱线特征。

融合路径只有 `rgbd_geometry_v4_fused_edges` 模型使用；当前稳定 v4 仍走旧特征路径。测试见 [`test_face_topology3d.py`](../../tests/test_face_topology3d.py)。

### [`geometry_rgbd_model.py`](../../src/sorting_vision/geometry_rgbd_model.py)

RGB-D 多姿态 KNN 模型与托盘 RGB 支持工具：

- `extract_rgbd_geometry_features()`：点云尺寸、分布、轮廓、可见面拓扑和可选融合棱线。
- `DepthGeometryModel`：标准化特征、多姿态 KNN、距离/类别间隔拒识、NPZ 保存加载和旧格式兼容。
- `detect_tray_roi_mask()` / `constrain_tray_roi()`：白色托盘 ROI 与标定参考约束。
- `detect_rgb_object_support()`：为深度实例拆分提供 RGB 支持。
- `train_rgbd_geometry_model()`：按批次、严格单实例、基础模型追加和融合特征训练。

新训练结果应写入 `models/experimental/rgbd/`，通过批次验证、视觉审查、多物体组成和延迟门槛后才能升级。测试见 [`test_rgbd_dataset.py`](../../tests/test_rgbd_dataset.py) 和 [`test_geometry_models.py`](../../tests/test_geometry_models.py)。

### [`grasp3d.py`](../../src/sorting_vision/grasp3d.py)

`find_suction_grasp()` 在对象内部搜索局部平面，检查吸盘直径、平面 RMSE、边缘余量、有效深度率和法向倾角，然后把位置、表面法向和接近方向变换到机器人坐标系。返回 `GraspCandidate`，其中包含 `Pose3D`、`GraspInfo` 和像素位置。

`rotation_matrix_to_quaternion()` 提供姿态转换。测试见 [`test_grasp3d.py`](../../tests/test_grasp3d.py)。

## 7. 数据集、采集与视觉审查

### [`rgbd_dataset.py`](../../src/sorting_vision/rgbd_dataset.py)

管理带标签的单物体 RGB-D 数据集：

- `normalize_rgbd_label()`：中文/英文标签归一化。
- `save_rgbd_dataset_sample()`：保存自包含样本及清单。
- `load_rgbd_dataset_entries()`：读取批次、类别、样本目录和元数据。
- `audit_rgbd_dataset()`：检查 RGB、深度、内参、标签、哈希和深度质量。
- `depth_preview()`：把深度生成可视预览。

测试见 [`test_rgbd_dataset.py`](../../tests/test_rgbd_dataset.py)。

### [`capture_assistant.py`](../../src/sorting_vision/capture_assistant.py)

单物体 D435if 交互拍摄助手：`CaptureAssistantState` 管理当前类别和数量，`CaptureQualityTracker` 检查有效深度、同步、画面运动、清晰度和曝光，`render_capture_assistant()` 生成预览面板。

使用 `rgbd-capture-assistant`，教程见 [D435if 数据集拍摄助手](D435if数据集拍摄助手.md)。`READY` 仅代表允许保存，不代表标签自动正确。测试见 [`test_capture_assistant.py`](../../tests/test_capture_assistant.py)。

### [`multi_capture.py`](../../src/sorting_vision/multi_capture.py)

多物体整盘测试采集：解析“类别:数量”组成、恢复场景编号、保存每次 RGB-D 帧和 `scene.json`，并检查重复帧。`MultiCaptureState` 管理场景与连拍进度。

使用 `rgbd-multi-capture`，教程见 [D435if 多物体批量测试拍摄](D435if多物体批量测试拍摄.md)。组成标签只能评估整帧数量/类别计数，不能自动生成逐实例真值。测试见 [`test_multi_capture.py`](../../tests/test_multi_capture.py)。

### [`rgbd_review.py`](../../src/sorting_vision/rgbd_review.py)

`build_rgbd_review()` 递归读取每帧的标注图、深度预览、结果 JSON 和健康 JSON，生成 RGB/深度联系表与 `review-manifest.json`。它会标出目标数、`unknown`、`selected` 和健康失败，但不会代替人工审图。

CLI 为 `rgbd-review`。教程见[视觉审查流程](视觉审查流程.md)，测试见 [`test_rgbd_review.py`](../../tests/test_rgbd_review.py)。

### [`rgbd_edge_audit.py`](../../src/sorting_vision/rgbd_edge_audit.py)

`audit_rgbd_edges()` 按批次导出 RGB 候选、深度候选、融合保留线、拒绝线、面分区、联系表和拓扑 JSON；`render_fused_edge_audit()` 负责单个对象可视化。

CLI 为 `rgbd-edge-audit`。颜色说明见 [RGB-D 结果颜色与字段说明](RGB-D结果颜色与字段说明.md)，融合实验结论见 [RGB-D 棱线融合试验报告](../reports/RGB-D棱线融合试验报告_20260908.md)。

## 8. 服务端与运动互锁

### [`interlock.py`](../../src/sorting_vision/interlock.py)

`MotionInterlock` 管理 `RUNNING`、`MOVING`、`SETTLING` 状态。运动开始会清除旧目标；停止后丢弃若干帧，并检查最短等待时间和连续画面稳定。`observe()` 根据当前图像更新状态，`status()` / `reason()` 提供服务端字段。

修改任何等待、稳定或状态转换逻辑都必须运行 [`test_motion_interlock.py`](../../tests/test_motion_interlock.py)。

### [`server.py`](../../src/sorting_vision/server.py)

`VisionService3D` 把相机、流水线和互锁组合为统一服务：

- `update()`：采集并处理新帧。
- `motion_start()` / `motion_stop()`：切换运动状态并清除旧选择。
- `health()`：合并相机、视觉和互锁健康信息。
- `handle()`：处理 `detect`、`motion_start`、`motion_stop`、`ack_pick`、`health` 请求。
- `serve_json_tcp()`：启动一行一个 JSON 的多线程 TCP 服务。

协议见根 [README 的 JSON/TCP 控制](../../README.md#jsontcp控制)，测试见 [`test_camera_server.py`](../../tests/test_camera_server.py)。

### 日常预测与演示

| 命令 | 用途 | 主要输出/注意事项 |

## 13. Python 集成示例

### 回放一帧并使用稳定 v4

```python
from sorting_vision.camera import load_rgbd_frame
from sorting_vision.config import load_config
from sorting_vision.geometry_rgbd_model import DepthGeometryModel
from sorting_vision.pipeline3d import VisionPipeline3D
from sorting_vision.rgbd import RGBDCalibration

config = load_config("config/d435if-initial.yaml")
calibration = RGBDCalibration.load("rgbd-calibration.json")
model = DepthGeometryModel.load(
    "models/stable/rgbd/geometry-rgbd-multipose-v4.npz"
)
pipeline = VisionPipeline3D(
    config=config,
    calibration=calibration,
    shape_model=model,
)

frame = load_rgbd_frame("data/scene-frame")
pipeline.process(frame)          # 第一帧用于建立稳定计数
results = pipeline.process(frame)

health = pipeline.health()
selected = next((item for item in results if item.selected), None)
if (
    health.get("ok") is True
    and selected is not None
    and selected.status.value == "PICKABLE"
):
    payload = selected.to_dict()
    print(payload["pose_3d"])
```

这里加载的 v4 来自旧 D415 数据，只能用于 D435if 迁移对照。实际控制还必须使用经 D435if 数据验证的模型，并经过 `MotionInterlock`/`VisionService3D`；不要把这个离线示例直接当机械控制循环。

### 接入新的 RGB-D 相机

实现与 `RGBDSource` 相同的接口：

```python
class MyRGBDSource:
    def read(self):
        # 返回已经对齐、内参和时间戳正确的 RGBDFrame
        ...

    def close(self):
        ...
```

必须保证彩色图与深度图对齐、深度比例正确、时间戳可比较。接入后先增加测试，再通过 `VisionService3D` 使用，不要直接绕过健康检查。

### 接入新的三维分类模型

实现 `ShapeModel3D.classify(...)`，返回 `LabelPrediction`。分类模型只能决定类别与置信度，不能自行设置 `selected=true` 或跳过抓取面检查。

```python
class MyShapeModel3D:
    def classify(
        self,
        points_camera_mm,
        color_crop_bgr,
        depth_crop_mm,
        crop_mask,
        intrinsics,
        crop_origin_uv,
    ):
        ...
```

新模型应先保存在 `models/experimental/`，使用独立批次和相同输入样本与稳定 v4 对照。
