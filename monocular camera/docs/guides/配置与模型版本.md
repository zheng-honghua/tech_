# 配置、路径与模型版本管理

更新：2026-10-02。配置决定设备、分割、分类、抓取与文件来源；模型版本决定特征语义。两者需要配套。

## 1. 当前配置怎么加载

CLI全局--config放子命令前；脚本参数按该脚本--help。省略路径读取本工程默认配置，不自动选择v6／v7／v8。

本单目load_config读取单个YAML，不支持双相机工程的extends递归继承。新现场复制完整配置再调整，不只写extends。两个工程的同名config.py能力不同。

相对模型／图片／背景路径按运行工作目录使用，所以先进入本工程根目录。不要在tech_调用相对路径又期待它自动进入子工程。

## 2. 参数分组

| 配置段 | 主要用途 | 更改后核对 |
|---|---|---|
| tray | 料盘尺寸和二维矫正尺度 | 实测尺寸、ROI |
| segmentation | RGB前景、形态学、面积与接触处理 | 轮廓和误拆／合并 |
| classification | 颜色、形状和接受条件 | 原型／模型、拒识与错误接受 |
| selection | 稳定帧与目标排序 | 连续帧、selected |
| rgbd | 深度范围、平面、同步、处理尺度 | 原深度、内参、平面和特征 |
| grasp | 吸盘尺寸、平整度与余量 | 真实吸盘及实际抓取面 |
| camera | RealSense／UVC流和重连 | 支持档位与设备 |
| network | 服务地址／端口 | 实际连接与超时 |
| motion_interlock | 运动／稳定互锁 | 动作通知与现场图像稳定 |

具体字段与默认值看config.py／YAML，不凭历史文档猜测。数据范围、像素、毫米、角度和时间单位明确，像素阈值随尺度核对。

本单目没有dual_view、侧模型、v7/v8视觉契约或双相机参数；需要这些功能进入独立stereo camera。

## 3. 模型分级与输入

stable保留原验证环境的推荐版本，换设备仍须复验。experimental为未推广候选；archive仅兼容／历史复现。v4是旧D415 RGB-D基线，D435if新现场没有自动继承其效果。

RGB模型不能代替真实深度；普通RGB-D与完整RGB轮廓／深度双掩膜契约不同。改变分割、填充、线段、面语义后重新提取特征并训练，保持指纹检查。

## 4. 新实验的文件规划

同一实验保存配置、模型、策略、来源ID与哈希、训练／校准／测试划分、失败记录、实际看图、报告。命名包含用途／版本／日期，给回放单独输出目录。

模型加载成功只证明格式可读；还要检查类别顺序、归一化来源、输入语义及应用结果。缺失颜色／形状不得补成虚假覆盖。

## 5. 配置修改的验证

用load_config确认类型和关键值，--help检查命令参数；新数据做实际看图和完整回放。只改路径不必重训，但路径换到不同标定／背景／模型可能改变行为，要核对来源。

本次教程维护算法变化为无，未替换默认配置或模型。使用入口见[单目手册](单目工程完整使用手册.md)，模块与参数见[模块说明](模块使用说明.md)和[CLI索引](CLI命令与参数索引.md)。
