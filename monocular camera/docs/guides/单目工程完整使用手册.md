# 单目工程完整使用手册

更新：2026-10-02。本工程支持一台RealSense的RGB-D三维主链及一台普通UVC的RGB开发。双相机采集／融合在独立[双相机工程](../../../stereo%20camera/docs/guides/双相机工程完整使用手册.md)，两个工程自己的环境分别使用。

## 1. 每次启动先确认环境

```powershell
Set-Location "C:\Users\d114\Desktop\tech_\monocular camera"
Get-Location
Test-Path .\pyproject.toml
Test-Path .\.venv\Scripts\python.exe
.\.venv\Scripts\python.exe `
    -c "import sys, sorting_vision; print(sys.executable); print(sorting_vision.__file__)"
.\.venv\Scripts\python.exe -m pip check
```

应指向monocular camera的.venv和src。(.venv)不会改变工作目录，也不证明包来自正确工程。后文显式调用本地Python，无需反复激活；排错见[环境篇](环境与相机排错.md)。

## 4. 普通USB相机开发

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli camera-live --source uvc --camera-index 0
```

索引要按实际画面确认，关闭其他相机程序再打开；Q退出。只有RGB，不能输出可执行深度；RGBDevelopmentPipeline保持pose／grasp为空、selected=false。

## 5. RealSense试拍

固定相机、料盘和照明，确认Viewer中的支持档位后关闭Viewer。当前d435if-initial.yaml请求RGB／深度1280×720、30 FPS，是迁移候选，现场需核验。

```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli `
    --config config\d435if-initial.yaml rgbd-capture-assistant `
    --dataset-root data\rgbd-new `
    --batch-id pilot-20261002 `
    --start-label empty_tray `
    --target-per-label 5
```

先空盘，READY后空格保存；放单物块选真实形状，移走手后保存；不同摆放5–10组，Q退出。目标计数不自动生成独立姿态。F是诊断覆盖，不等于合格采集。

文件为color.png、depth.npy、metadata.json和深度预览，数据根manifest记录批次。depth.npy是原始数值，通过depth_scale_to_mm换毫米，不能用伪彩图测量。

## 6. 检查保存结果

```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli rgbd-dataset-audit `
    --data-root data\rgbd-new `
    --output-report output\pilot-audit-20261002.json
```

打开原RGB、原深度预览和metadata，检查孔洞、截断、标签、反光与图深对齐。原始深度档位和对齐后的RGB尺寸不同，预览块状不能直接称失焦。

## 7. 空盘平面与机械外参

将ACTUAL_SAMPLE_ID换成实际打印的空盘样本：
```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli `
    --config config\d435if-initial.yaml rgbd-calibrate `
    --background-dir data\rgbd-new\pilot-20261002\empty_tray\ACTUAL_SAMPLE_ID `
    --output output\rgbd-calibration-20261002.json
```

默认camera_to_robot是单位矩阵，开发结果仍属相机系。实际机械坐标必须提供实测4×4变换并核对方向、单位和工作区。平面拟合成功不代表机器人外参通过。

## 8. 离线检测与联系表

```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli `
    --config config\d435if-initial.yaml rgbd-detect `
    --frame-dir data\rgbd-new\pilot-20261002\cone\ACTUAL_SAMPLE_ID `
    --rgbd-calibration output\rgbd-calibration-20261002.json `
    --output-dir output\pilot-replay-20261002\frame-0001
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli rgbd-review `
    --results-root output\pilot-replay-20261002 `
    --output-dir output\pilot-contact-20261002
```

物块和空盘的sample-id不同。rgbd-review读取已检测结果，不直接读原始数据；多帧回放模板见[审查教程](视觉审查流程.md)。实际查看ROI、数量、掩膜、类别、深度与抓取状态。

## 9. 实时RGB-D预览

准备上述同安装的标定后：
```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli `
    --config config\d435if-initial.yaml camera-live `
    --source realsense `
    --rgbd-calibration output\rgbd-calibration-20261002.json
```

主模型可显式--rgbd-shape-model指定配套文件。原stable v4用D415训练，D435if仅迁移基线，不能凭目录名用于机械执行。实时选择需要连续稳定、health和抓取条件，离线单帧结果不能证明它们。

## 10. 正式采集与训练

按实体／批次分开拟合、阈值校准、最终测试，相邻连拍不跨集合。单目采集助手没有双机专用split／instance-id／color-id参数，划分记录在采集计划、批次和审查中，训练输入只给明确拟合集。

RGB和RGB-D输入不同，详见[模型教程](模型训练与后端.md)。新模型存experimental，记录特征语义与数据来源，改分割后重新提特征，禁止旧模型静默消费新语义。

## 11. 安全字段与服务

health、PICKABLE、selected、pose_3d、grasp和外部互锁共同判断。颜色／形状标签不等于可抓，DEPTH_INVALID／NO_GRASP_SURFACE分别处理。服务逐行JSON／TCP，motion_start／stop是状态通知而非机器人执行命令，见[接口篇](服务接口与部署.md)。

## 12. 换机与保存

换设备、位置、焦距、分辨率、光照、料盘或吸盘时按[迁移篇](D435if迁移与重新标定.md)重新核验。备份原图、原深度、metadata、manifest、标定、模型／策略、审查与报告。output中的唯一实验快照不可一概清空。
