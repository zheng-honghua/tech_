# RGB-D 识别结果视觉审查流程

本项目把人工视觉审查作为每次数据集测试、模型训练和识别算法修改后的必做验收项。准确率、召回率和混淆矩阵不能替代图像审查。

## 生成审查材料

在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli rgbd-review `
  --results-root "output\本次检测结果" `
  --output-dir "output\本次检测结果-审查"
```

程序会递归读取每帧的 `annotated-rgbd.png`、`depth-preview.png`、`results-v2.json` 和 `health.json`，生成：

- `annotated-contact-sheet.jpg`：RGB、托盘 ROI、检测框和类别总览。
- `depth-contact-sheet.jpg`：对应深度画面总览。
- `review-manifest.json`：逐帧目标数、未知类别、健康状态和缺失文件清单。

清单中的 `PENDING_HUMAN_VISUAL_REVIEW` 是有意保留的：生成图片不等于完成审查。

## 必查项目

1. ROI 只覆盖白色托盘内部和边缘，托盘外物体没有进入候选。
2. 每个实物对应一个检测区域，没有漏检、粘连、重复拆分或托盘碎片误检。
3. RGB 框、深度色块和类别标签对应同一物块。
4. 逐张打开总览中异常帧，重点检查 `unknown`、目标数突变、深度缺失和边缘截断。
5. 在本次算法的 Markdown 测试报告中写明审查批次、异常帧、视觉结论及是否接受；修改算法后重新生成并复查。

## 审查记录模板

```text
审查数据：multi-02、multi-03
审查材料：output/.../annotated-contact-sheet.jpg、depth-contact-sheet.jpg
异常帧：multi-03/frame-06（一个物块被拆成两个候选）
结论：六棱柱改善；分割异常仍需保留为已知问题，不用于正式验收。
```
