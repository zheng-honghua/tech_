# RGB-D 识别结果颜色、文字与安全状态说明

本文用于判读 `rgbd-detect`、`rgbd-review`、联系表和 `results-v2.json`。颜色和文字均来自当前代码，不是人工真值标注。

## 最重要的判读原则

- 检测框颜色表示当前对象的安全状态或是否被选中，不表示形状分类一定正确。
- 绿色框只代表该对象当前通过了类别和抓取面门限；它仍可能发生形状误分类。
- 形状识别正确的对象也可能因为遮挡、深度孔洞或没有合格吸附面而显示为橙色、红色或紫色。
- `PICKABLE` 不等于机械臂可以立即动作。控制端必须同时确认整帧 `health.ok=true`、对象 `status=PICKABLE`、`selected=true`，并通过运动互锁。
- RGB 单目开发结果固定为 `DEPTH_REQUIRED`，只能显示和调试，不能驱动抓取。

## 标注图中的线框和区域

| 画面元素 | 含义 | 注意事项 |
| --- | --- | --- |
| 黄色粗轮廓 | 当前托盘 ROI | ROI 外区域会被压暗。轮廓异常扩大、缩小或偏移时，应先检查托盘检测和空托盘标定。 |
| 对象矩形框 | RGB-D 分割得到的一个候选实例 | 一个框不一定等于一个真实物体；粘连会少框，碎片和重复拆分会多框。 |
| 框内/框旁文字 | 颜色、形状、置信度和安全状态 | 是模型输出，不是标签或人工答案。 |
| 十字标记 | 当前候选吸附点像素 | 仅表示找到了局部候选点；只有最终安全条件全部满足时才能使用。 |
| ROI 外压暗区域 | 非工作区 | 这里的物体不应进入正常抓取候选；若进入，应记为 ROI 或分割异常。 |

## 检测框颜色

OpenCV 在代码中使用 BGR 数值，表中按人眼看到的颜色描述。

| 颜色 | 状态/来源 | 当前代码含义 |
| --- | --- | --- |
| 绿色 | `PICKABLE` | 有效深度、边界间距、颜色与形状置信度、吸附面分数均通过对象级门限。它不是“分类正确”的绿色真值标记。 |
| 亮黄橙色 | `UNCERTAIN` | 颜色或形状为 `unknown`，或者颜色/形状置信度低于配置门限。 |
| 红色 | `OCCLUDED` | 候选接触处理边界，或与边界的像素间距低于安全门限；轮廓可能不完整。 |
| 紫色/品红色 | `DEPTH_INVALID` | 对象有效深度比例不足，或整帧深度、托盘平面、RGB-D 同步健康检查失败。 |
| 深橙色 | `NO_GRASP_SURFACE` | 分类可接受，但没有找到满足吸盘直径、平面度、边缘余量、有效深度率和法向限制的表面。 |
| 亮蓝色 | `selected=true` | 当前帧中被选为目标的对象。蓝色会覆盖原状态颜色；代码只会从 `PICKABLE` 中选择。仍需通过连续帧稳定和控制端互锁。 |

`DEPTH_REQUIRED` 是 RGB-only 开发状态，当前 RGB-D 标注色表不为它分配普通检测框颜色，因为它不应进入三维执行链路。

## 两行文字怎么读

典型标注如下：

```text
cyan/tri shape=0.93
NO_GRASP_SURFACE color=0.98 grasp=0.61
```

第一行：

- `cyan`：机器使用的颜色 ID；对应中文名称记录在 JSON 的 `color_name`。
- `tri`：形状 ID `triangular_prism` 的显示缩写，即“三棱柱”。它不是“二维三角形”，也不是新增类别。
- `shape=0.93`：形状模型给出的内部置信度。当前稳定 v4 是标准化多姿态 KNN，该值由邻居距离、类别拒识阈值和类别间距计算，不是校准后的真实概率，不能解释成“有 93% 概率一定正确”。

第二行：

- `NO_GRASP_SURFACE`：对象安全状态。
- `color=0.98`：颜色分类置信度。
- `grasp=0.61`：吸附面质量分数；没有候选吸附面时为 `0.00`。

完整置信度还包括 `segmentation`、`pose` 和 `combined`。`combined` 是分割、颜色、形状、位姿、抓取五项分数的几何平均，用于在多个 `PICKABLE` 候选中排序，不是整套系统的实测准确率。

## 形状缩写

只有以下五种形状在图片上使用短名称，其余类别直接显示完整英文 ID。

| 图片短名 | JSON `shape_id` | 中文含义 |
| --- | --- | --- |
| `tri` | `triangular_prism` | 三棱柱 |
| `pent` | `pentagonal_prism` | 五棱柱 |
| `hex` | `hexagonal_prism` | 六棱柱 |
| `cyl` | `cylinder` | 圆柱体 |
| `box` | `cuboid` | 长方体 |

例如，三棱锥仍显示为 `triangular_pyramid`，四棱锥显示为 `square_pyramid`。判断类别时以 `results-v2.json` 中的 `shape_id` 和 `shape_name` 为准，不要只凭图片缩写猜测。

## 为什么会出现很多 `tri`

`tri` 表示模型把对象识别为三棱柱。它可能是正确结果，也可能是五棱柱、六棱柱或棱锥的误分类。常见原因包括：

- 当前视角只看见少量平面，五棱柱或六棱柱的可见轮廓与三棱柱相似。
- 深度孔洞或边缘截断使点云尺寸、轮廓和面拓扑不完整。
- 接触物体被合并，或单个物体被拆成多个深度碎片。
- 同色面之间的弱棱没有被深度/RGB 特征稳定捕获。
- 训练姿态、距离、光照和现场画面分布不同。

因此，`tri shape=0.9x` 仍可能是高置信误判。发现大量 `tri` 时，应同时查看 RGB、深度联系表、实例裁剪和混淆统计，不能通过改显示名称解决。

## 状态的判定顺序

当前对象级状态按以下顺序判定，前面的失败会优先覆盖后面的状态：

1. 对象有效深度不足：`DEPTH_INVALID`。
2. 接触边界或安全间距不足：`OCCLUDED`。
3. 颜色/形状未知或置信度不足：`UNCERTAIN`。
4. 没有合格吸附面或抓取分数不足：`NO_GRASP_SURFACE`。
5. 全部通过：`PICKABLE`。

如果整帧健康检查失败，已经分析出的所有候选都会统一改为 `DEPTH_INVALID`，并清除 `selected`。因此同一帧大量紫框通常应先检查整帧 `health.json`，而不是逐个调整分类器。

## `PICKABLE`、`selected` 和真正可执行的区别

- `PICKABLE` 是单个对象通过对象级门限。
- `selected=true` 是系统从本帧所有 `PICKABLE` 对象中，按 `confidence.combined` 选出的一个候选，并且已经满足配置要求的连续帧稳定性。
- 当前配置默认要求连续 2 帧稳定；第一帧即使有 `PICKABLE`，也可能仍是 `selected=false`。
- 离线逐帧回放经常在每一帧后重置跟踪状态，所以出现 `PICKABLE` 但所有对象均为 `selected=false` 是正常现象，不代表系统没有检测到可抓对象。
- 机械动作还必须服从 TCP 服务状态、运动开始/停止确认、稳定等待和 `ack_pick` 规则。

安全硬规则：只有 RGB-D 结果同时满足 `health.ok=true`、`status=PICKABLE` 和 `selected=true` 时，控制端才可继续使用 `pose_3d`；其余结果均不得驱动机械臂。

## 联系表顶部文字

`rgbd-review` 的每个小图会显示类似：

```text
objects=4 unknown=1 selected=0 health=OK
```

| 字段 | 含义 |
| --- | --- |
| `objects` | 该帧输出的候选框数量，不是已确认的真实物体数。 |
| `unknown` | `shape_id=unknown` 的候选数。 |
| `selected` | `selected=true` 的候选数；正常执行链路最多应为 1。 |
| `health=OK` | 整帧通过深度、托盘平面和同步检查。 |
| `health=FAIL` | 整帧不可执行；具体原因查看同目录 `health.json`。 |

常见整帧失败原因：

| `health.reason` | 含义 |
| --- | --- |
| `insufficient_tray_depth` | 托盘 ROI 内有效深度不足。 |
| `tray_plane_not_visible` | 无法可靠看到或估计托盘平面。 |
| `tray_plane_shift_exceeded` | 当前托盘平面相对标定位置漂移超过门限。 |
| `rgb_depth_out_of_sync` | RGB 与深度时间差超过允许值。 |
| 托盘 ROI 相关错误 | 托盘定位失败、异常扩大或与参考区域不匹配；以 `health.json` 的原始字符串为准。 |

## `results-v2.json` 的关键字段

| 字段 | 正确用途 | 常见误读 |
| --- | --- | --- |
| `color_id` / `color_name` | 机器 ID / 中文显示名 | 不应只从框色推断物体颜色，框色是状态色。 |
| `shape_id` / `shape_name` | 机器形状 ID / 中文显示名 | 图片中的 `tri` 只是 `triangular_prism` 的缩写。 |
| `class_key` | `颜色ID:形状ID` 的组合键 | 不是置信度或数据集标签来源。 |
| `confidence` | 分割、颜色、形状、位姿、抓取和综合分数 | 各分数不是统一校准的概率，不能直接当准确率。 |
| `status` | 对象级安全状态 | `PICKABLE` 不代表已被选中。 |
| `selected` | 当前可执行候选标记 | 必须与 `PICKABLE`、整帧健康和互锁一起检查。 |
| `pose_3d` | 机器人使用的三维位姿候选 | 非安全状态下即使字段存在也不得执行。 |
| `grasp` | 吸盘直径、平面度、边缘余量、有效深度率和分数 | 十字点存在不代表已授权抓取。 |
| `bbox_px` | RGB 图像上的候选外接矩形 | 不是真实轮廓，也不保证一框一物。 |
| `diagnostics` | 调试特征、掩膜尺寸和抓取像素等诊断数据 | 诊断字段可随算法版本增加，不宜作为稳定控制协议。 |

`center_mm` 和 `angle_deg` 是旧界面兼容字段，真实控制使用 `pose_3d`。

## RGB-D 棱线审查图的颜色

`rgbd-edge-audit` 生成的颜色与普通检测框不是同一套含义：

| 文件/颜色 | 含义 |
| --- | --- |
| `faces.png` 多种半透明颜色 | 不同的深度平面分区；颜色只是区分面编号，没有类别含义。 |
| `rgb-candidates.png` 黄色/亮黄橙像素 | Lab 亮度和色度梯度得到的宽松 RGB 内部棱候选，尚未证明是真实三维棱。 |
| `depth-candidates.png` 蓝色像素 | 相邻深度平面形成的深度棱候选。 |
| `fused.png` 绿色线 | RGB 和深度面直接共同支持的保留线。 |
| `fused.png` 橙色线 | 由单侧候选出发，但通过两侧局部深度平面复核的保留线。 |
| `rejected.png` 红色线 | RGB 中明显、但没有可靠深度变化支持的拒绝线，常见于纹理、阴影或反光。 |

候选线多不等于识别更好。审查时要检查真实弱棱是否被保留、阴影是否被拒绝、孔洞边缘是否没有被补成棱，以及曲面是否没有产生多面体假棱。

## 其他工具中的颜色不要混用

不同命令各自使用颜色表达诊断信息，不能套用 RGB-D 检测框的状态图例。

| 工具/画面 | 颜色含义 |
| --- | --- |
| `rgbd-capture-assistant` | 顶部状态为绿色 `READY` 时，当前深度率、静止程度、清晰度和曝光检查允许正常保存；黄橙色 `WAIT` 表示至少一项尚未满足。`F` 强制保存只绕过采集质量等待，不会把样本自动变成正确标签。 |
| RGB-only 开发画面 | 所有框固定为黄橙色并标出 `RGB only`，状态是 `DEPTH_REQUIRED`；这里的橙色不是三维链路中的 `UNCERTAIN`，而是明确表示不可抓取。 |
| `predict-image` 单图结果 | 绿色框表示模型接受分类，橙色框表示拒识/`unknown`；它只评估二维形状分类，不代表有深度或可抓取。 |
| `geometry-edge-audit` 原始线 | 橙色线是清理前的原始内部线段。 |
| `geometry-edge-audit` 合并线 | 绿色线是共线合并和拓扑清理后的线段；紫色点是度数至少为 3 的交点，蓝青色点是度数较低的端点/连接点。它们都是二维诊断，不是抓取状态。 |
| `rgbd-face-audit` | 不同半透明颜色区分对象内的不同深度平面，`O1F0` 表示第 1 个对象的第 0 个面。颜色不表示面类别、好坏或能否吸附。 |

采集助手显示 `READY` 也只说明当前画面质量达到保存条件。保存前仍必须人工确认物体类别、标签选择、画面内物体数量、手部遮挡和空托盘背景是否正确。

## 评估数字的注意事项

- “检测数量匹配”只表示预测框数与期望物体数一致，不表示形状类别正确。
- “整帧组成匹配”要求数量和各类别计数都匹配，但在没有逐实例配对真值时，仍不能当作逐实例准确率。
- “47/55”是 `multi-02/03` 中临时已审、排除歧义标签后的开发回放结果，不是独立测试集泛化准确率。
- 单物体准确率约 85% 不意味着多物体整帧也有 85% 成功率；多物体还叠加 ROI、粘连/拆分、遮挡、深度孔洞和每个实例都要正确的要求。
- 联系表中的绿色框数量不能当分类正确数；必须与人工标签或组成标签比较。
- `unknown` 是主动拒识，通常比高置信误分类更安全，但会降低可抓取覆盖率。
- 同批训练回放、按批次验证、多物体组成评估和真实在线抓取成功率必须分别报告，不能混用口径。

## 快速排查

| 现象 | 优先检查 |
| --- | --- |
| 大量红框 | ROI 边界、物体是否贴边、候选间距、物体是否被截断。 |
| 大量紫框 | `health.json`、深度孔洞、托盘平面漂移、RGB-D 同步和相机距离。 |
| 大量亮黄橙框 | `unknown` 原因、颜色/形状置信度、训练数据姿态与现场域差异。 |
| 大量深橙框 | 吸盘尺寸、可见顶面、表面倾角、平面度、边缘余量和有效深度。 |
| 大量 `tri` | 五/六棱柱与棱锥混淆、弱棱漏检、深度边缘截断和多物体分割。 |
| 框数比实物多 | 托盘边缘碎片、单物体深度断裂、反光/孔洞导致重复拆分。 |
| 框数比实物少 | 接触物体粘连、ROI 漏掉物体、前景高度不足或深度缺失。 |
| 有绿框但 `selected=0` | 连续帧稳定尚未满足，或离线回放每帧重置了跟踪。 |

每次测试应同时保留并查看 `annotated-rgbd.png`、`depth-preview.png`、`results-v2.json`、`health.json` 以及 RGB/深度联系表；只看其中一种输出不足以判断问题来源。
