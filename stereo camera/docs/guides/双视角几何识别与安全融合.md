# 双视角几何识别与安全融合

本指南对应“俯视 D435if RGB-D 主导、侧置 USB RGB 辅助”的实现。侧相机只改变形状类别与形状置信度；深度、数量、三维位姿、抓取面和运动安全始终来自俯视 RGB-D。控制端仍只能执行同时满足 `status=PICKABLE` 和 `selected=true` 的结果。

实际拍摄时如何区分形状真值与颜色真值、判断三画面质量、组织A/B/C实体及50/15/15划分，见[双视角形状与颜色数据采集完整教程](双视角形状与颜色数据采集完整教程.md)。

当前 `temporary` 外参只通过开发放宽门槛，严格比赛指标仍未通过；当前工程也没有完整的 11 类实拍双视角数据集。因此现在可以采集、训练、离线审查和调试，不能宣称已经达到比赛识别率，也不能把实验模型直接用于正式分拣。

## 3. 单物体成对采集

推荐用三画面助手；它显示俯视 RGB、俯视深度和侧视 RGB，只保存最新一对同步帧：

```powershell
python scripts\dual_rgbd_side_capture.py `
  --config config\dual\temporary.yaml `
  --dataset-root data\dual --platform-id temporary `
  --batch-id train-A-red-20260914 --split train `
  --instance-id A --color-id red --target-per-label 10
```

按键：`0–9` 选择前十项，`N/P` 可遍历全部 12 项（空盘+11类），`SPACE` 合格保存，`F` 强制保存并记录质量覆盖，`A` 跳到下一个未完成类别，`Q` 退出。正式数据不要使用 `F`。

建议按以下互斥划分分别运行，不能把同一摆放的连续帧放入不同划分：

- `train`：每类 50 组，实体 A/B，覆盖五种颜色。
- `probability_calibration`：每类 15 组，实体 A/B，但日期、布局和光照不同。
- `final_holdout`：每类 15 组，只用训练阶段从未出现的实体 C。

每类至少三个不同尺寸实体；实例 ID 和颜色不能留为 `UNSPECIFIED`。程序会记录图像哈希，训练审计会拒绝跨划分重复图和实体 C 泄漏。

### 深度预览看起来发虚时

D435if深度没有RGB式自动对焦。当前原始深度档位是`848×480`，SDK把它对齐到`1920×1080`彩色坐标后再保存，因此预览中的块状、锯齿和边缘发软并不等于失焦。先对已拍数据运行质量审查：

```powershell
.\.venv\Scripts\python.exe scripts\audit_dual_depth_quality.py `
  --dataset-root data\dual\temporary `
  --output-dir output\depth-quality-audit
```

重点看有效率、中央料盘孔洞和生成的最差帧联系表。不要用锐化或无条件孔洞填充修饰预览；这会把虚构深度带入点云和抓取边缘。若要改变原生深度分辨率，必须先在RealSense Viewer确认该RGB/深度/FPS组合可同时启动，然后重拍空盘、训练、校准和最终留出数据，旧新profile不能混训。

如果日志出现`mono_pipeline_no_object`或`tray_roi_reference_mismatch`，表示该照片被单目正式质量门拒绝；不要为了增加训练数量强行绕过，应检查本批空盘参考、照明、低饱和黄色物块和靠盘边姿态。首批实测细节见[双视角单目主链融合与回归报告](../reports/双视角单目主链融合与回归报告_20260916.md)。
