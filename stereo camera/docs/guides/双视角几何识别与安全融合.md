# 双视角几何识别与安全融合

本指南对应“俯视 D435if RGB-D 主导、侧置 USB RGB 辅助”的实现。侧相机只改变形状类别与形状置信度；深度、数量、三维位姿、抓取面和运动安全始终来自俯视 RGB-D。控制端仍只能执行同时满足 `status=PICKABLE` 和 `selected=true` 的结果。

实际拍摄时如何区分形状真值与颜色真值、判断三画面质量、组织A/B/C实体及50/15/15划分，见[双视角形状与颜色数据采集完整教程](双视角形状与颜色数据采集完整教程.md)。

当前 `temporary` 外参只通过开发放宽门槛，严格比赛指标仍未通过；当前工程也没有完整的 11 类实拍双视角数据集。因此现在可以采集、训练、离线审查和调试，不能宣称已经达到比赛识别率，也不能把实验模型直接用于正式分拣。

## 3. 单物体成对采集

推荐用三画面助手；它显示俯视 RGB、俯视深度和侧视 RGB，只保存最新一对同步帧：

```powershell
python scripts\dual_rgbd_side_capture.py `
  --config config\dual\temporary.yaml `
  --dataset-root data\dual --platform-id temporary `
  --batch-id train-A-red-20260914 --split train `
  --instance-id A --color-id red --target-per-label 10
```

按键：`0–9` 选择前十项，`N/P` 可遍历全部 12 项（空盘+11类），`SPACE` 合格保存，`F` 强制保存并记录质量覆盖，`A` 跳到下一个未完成类别，`Q` 退出。正式数据不要使用 `F`。

建议按以下互斥划分分别运行，不能把同一摆放的连续帧放入不同划分：

- `train`：每类 50 组，实体 A/B，覆盖五种颜色。
- `probability_calibration`：每类 15 组，实体 A/B，但日期、布局和光照不同。
- `final_holdout`：每类 15 组，只用训练阶段从未出现的实体 C。

每类至少三个不同尺寸实体；实例 ID 和颜色不能留为 `UNSPECIFIED`。程序会记录图像哈希，训练审计会拒绝跨划分重复图和实体 C 泄漏。

## 5. 逐帧视觉审查

第一次尚无侧视模型时，省略 `--side-shape-model`，`dual-review` 会先生成原始俯视/侧视/深度联系表。完成首次训练后加入模型参数重跑，它会额外生成投影 ROI 标注、schema v2 结果及 `dual-evaluation-records.jsonl`：

```powershell
python -m sorting_vision.cli --config config\dual\temporary.yaml dual-review `
  --samples-root data\dual\temporary `
  --output-dir output\dual-review `
  --platform-id temporary `
  --dual-calibration config\dual\temporary\calibration.json `
  --side-background config\dual\temporary\side-background.png `
  --side-shape-model models\side-geometry.npz `
  --background-dir data\rgbd-background
```

查看三画面联系表后，人工生成一行一个 JSON 的审查文件。每一帧必须逐项填写，不能整批一键批准：

```json
{"sample":"temporary/train-A-red-20260914/triangular_prism/sample-0001","approved":true,"true_label":"三棱柱","roi_ok":true,"association_ok":true,"shadow_ok":true,"depth_ok":true,"instance_split_ok":true,"notes":"无遮挡"}
```

应用审查：

```powershell
python -m sorting_vision.cli dual-review-apply `
  --samples-root data\dual `
  --reviews data\dual\review-decisions.jsonl `
  --shape-registry config\shapes\competition-11.yaml
```

需检查：投影多边形、跨视角对应、遮挡、阴影/反光、深度孔洞、实例合并/拆分、类别冲突以及帧 ID。`human_reviewed=true` 只在五项检查和 `approved` 全为真时写入。

多物体场景还必须按标注图上的 `object_id` 逐件记录真实类别、侧视可见率和遮挡；对象数及类别多重集合必须与采集时的 `composition` 完全一致：

```json
{"sample":"competition/multi-object/final_acceptance/final-01/scene-0001","approved":true,"roi_ok":true,"association_ok":true,"shadow_ok":true,"depth_ok":true,"instance_split_ok":true,"objects":[{"object_id":"object-1","true_label":"三棱柱","side_visible_ratio":0.92,"side_occluded":false,"association_ok":true},{"object_id":"object-2","true_label":"圆锥","side_visible_ratio":0.41,"side_occluded":true,"association_ok":true}]}
```

示例为格式说明，实际每盘必须列全5–8件。漏标、重复 `object_id`、可见率越界、对应未确认或类别组成不符都会拒绝整帧批准。

## 6. 训练经典侧视模型

训练程序只读人工审查数据，用 `train` 训练，用 `probability_calibration` 独立拟合距离/间隔拒识阈值并比较标准化分组 KNN 与 OpenCV RTrees；选择优先级固定为零错误接受、宏召回、覆盖率、延迟：

```powershell
python -m sorting_vision.cli dual-side-train `
  --samples-root data\dual\competition `
  --side-background config\dual\competition\side-background.png `
  --shape-registry config\shapes\competition-11.yaml `
  --output models\side-geometry.npz `
  --report output\dual-side-training.json
```

模型保存完整类别顺序和注册表哈希。修改类别注册表后，旧模型会明确拒绝加载，必须重新训练。

## 7. 概率校准与三种融合器选择

在 `probability_calibration` 记录上执行：

```powershell
python -m sorting_vision.cli dual-fusion-fit `
  --records output\dual-review\dual-evaluation-records.jsonl `
  --shape-registry config\shapes\competition-11.yaml `
  --output models\dual-fusion-policy.json `
  --report output\dual-fusion-fit.json
```

程序分别拟合俯视/侧视温度，比较质量加权概率和、质量加权对数概率积和 L2 正则通用 Top‑2 逻辑融合器。三个方法都只能在俯视 Top‑2 中重排。选择顺序为：错误接受数为零 → 宏召回最高 → 接受覆盖率最高 → 延迟最低。

## 8. 实验性 MobileNetV3-Small

这条分支不是默认模型。合成图只能作为预训练和不变性测试，不能参与温度校准、阈值选择或最终成绩：

```powershell
python -m sorting_vision.cli dual-side-cnn-train `
  --samples-root data\dual\competition `
  --side-background config\dual\competition\side-background.png `
  --shape-registry config\shapes\competition-11.yaml `
  --epochs 30 --synthetic-pretrain-per-class 20 `
  --output models\experimental\side-cnn.pt

python -m sorting_vision.cli dual-side-cnn-export `
  --checkpoint models\experimental\side-cnn.pt `
  --output-dir models\experimental\side-cnn-export `
  --target-backend both

python -m sorting_vision.cli dual-side-cnn-calibrate `
  --model-dir models\experimental\side-cnn-export `
  --samples-root data\dual\competition `
  --side-background config\dual\competition\side-background.png `
  --shape-registry config\shapes\competition-11.yaml `
  --report output\dual-side-cnn-calibration.json
```

第三条命令只读取已人工审查的实拍 `probability_calibration` 样本，并把零错误接受优先选择的置信度/间隔阈值写入共享 `metadata.json`；不能用合成图替代。N100 使用校准后的 OpenVINO FP16。Orin Nano 必须把同一导出目录复制到目标机，再运行：

```bash
python -m sorting_vision.cli dual-side-tensorrt-build \
  --model-dir models/experimental/side-cnn-export
```

它调用目标机的 `trtexec` 生成 FP16 engine。TensorRT engine 与 JetPack/TensorRT/GPU 绑定，不要在 Windows 上生成后复制。运行参数为 `--fusion-backend auto|opencv|openvino|tensorrt`；经典 KNN/RTrees 始终显示实际后端 `opencv`。

在N100和Orin上分别用同一批 `probability_calibration`/`final_holdout` 实拍样本检查输出一致性和P95延迟：

```powershell
python -m sorting_vision.cli dual-side-backend-check `
  --model-dir models\experimental\side-cnn-export `
  --samples-root data\dual\competition `
  --side-background config\dual\competition\side-background.png `
  --shape-registry config\shapes\competition-11.yaml `
  --output output\dual-side-backend-check.json
```

默认要求OpenCV、OpenVINO和TensorRT三者全部实际加载、每张图的类别与接受/拒识状态一致且P95不超过1秒；缺少后端会记录在报告中并返回失败。若某台设备只具备其中两个后端，可重复传入 `--backend opencv --backend openvino` 做局部诊断，但不能代替最终三后端验收。

## 10. 最终验收

先在N100和Orin Nano各自运行同一份最终数据的 `dual-review`，分别加上 `--deployment-target n100` 与 `--deployment-target orin_nano`，再合并两份JSONL记录用于最终判定：

```powershell
python -m sorting_vision.cli dual-evaluate `
  --records output\competition-final\dual-evaluation-records.jsonl `
  --output output\competition-final\promotion.json
```

必须同时满足：11类最终留出融合宏召回比单目高至少3个百分点、单件和多件错误接受均为0、30个开发和30个最终多物体场景齐全、最终多物体无漏检、安全状态非法升级为0、未遮挡对应错误为0、投影P95≤3 px、配对P95≤50 ms、Orin/N100端到端P95均≤1秒，并完成全部逐帧人工审查。任一项不满足时，只保留双视角诊断，正式运行继续使用单目稳定链路。
