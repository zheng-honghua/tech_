# 双视角采集、回放与验收

更新：2026-10-02。将已采数据、标定、背景和模型接起来。初次采集见[完整手册](双相机工程完整使用手册.md)。

## 1. 运行前的配套文件

当前配置、主RGB-D标定或空盘帧、双机标定、侧背景、注册表、模型和融合策略必须匹配同平台、尺寸、哈希与语义。普通temporary.yaml不自动加载实验侧／联合模型，不是v8配置。

| 资料 | 检查内容 |
|---|---|
| 原始配对样本 | 四文件、帧ID、同步、哈希 |
| 主空盘／RGB-D标定 | 相机、料盘平面和真实机械变换 |
| 双机标定 | 原生尺寸、质量profile、投影／尺度门 |
| 侧背景 | 同灯光、焦距、盘位置 |
| 模型／注册表／策略 | 类别顺序、特征契约与指纹 |

采集见[形状颜色篇](双视角形状与颜色数据采集完整教程.md)，内参／AprilTag见[标定篇](三AprilTag双相机采集与标定程序.md)。


## 3. 原始联系表与应用联系表

无有效标定时先按[视觉审查](视觉审查流程.md)生成原始三联图，不运行融合。

标定、背景和采集哈希匹配后：
```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli `
    --config config\dual\temporary.yaml dual-review `
    --samples-root data\dual\temporary\pilot-blue-20261002 `
    --output-dir output\pilot-application-review-20261002 `
    --platform-id temporary `
    --dual-calibration config\dual\temporary\calibration.json `
    --side-background config\dual\temporary\side-background.png `
    --background-dir data\rgbd-background\temporary-empty
```

background-dir需提前采对应单RGB-D空盘；可替换为--rgbd-calibration实际JSON。命令校验采集哈希和平台，历史不匹配时正常拒绝。

可显式传--rgbd-shape-model、--side-shape-model、--cross-view-shape-model、--fusion-policy。未给侧模型可做基础审查，不能称已验证模型融合。输出标注、dual-results-v2.json、联系表和评估资料，必须实际查看。

## 4. 实时双视角预览

准备真实对应文件后：
```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli `
    --config config\dual\temporary.yaml camera-live `
    --source dual `
    --side-camera-index 1 `
    --platform-id temporary `
    --background-dir data\rgbd-background\temporary-empty `
    --dual-calibration config\dual\temporary\calibration.json `
    --side-background config\dual\temporary\side-background.png
```

基础命令检查设备、同步和主链，未加载三套实验模型。v8需要独立配置、配套颜色与模型、observed10注册表及主模型，见[v8指南](../v8双相机融合实验复现.md)。

Q退出；--max-frames 30 --headless做有界实机检查，仍打开设备。先关闭占用程序。

## 5. 融合状态

| 状态 | 含义 |
|---|---|
| FUSED | 侧视参与允许范围内的形状判定 |
| TOP_ONLY | 保留主视，查看side_reason／rejection_reason |
| SIDE_MISSING | 无侧帧 |
| SIDE_OCCLUDED | 投影重叠或可见性不足 |
| UNSYNCED | 双机配对门失败 |
| CALIBRATION_INVALID | 平台、尺寸、几何或平面门失败 |
| CONFLICT | 高置信证据冲突 |

点云投影、唯一对应、遮挡与歧义共同约束；同色或最近中心不单独强行匹配。温度、权重、概率门读取当前配置／策略，不把早期数值写成所有版本通用规则。

## 6. 实验回放

replay_dual_application.py读取冻结输入和模型；使用新output-dir避免覆盖已审结果。show-side-geometry是参考包围体，不是物理棱；show-side-edges是RGB候选；show-sparse-geometry是稀疏候选。详见[平台与重建](更换平台与双视角稀疏三维重建复现.md)。

串行计时、固定输入／线程；披露读图、绘图、采集、通信、机械是否计入。冷启动selected=false不验证连续帧现场行为。

## 7. 最终验收

```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli dual-evaluate `
    --records output\competition-final-holdout.jsonl `
    --output output\competition-promotion-report.json
```

输入是经过实际审查、带真值／状态／对应／时延的评估JSONL，不是metadata清单。当前评估器检查competition、final_holdout、human_reviewed、多物块和目标机证据；完整gates以代码和报告为准。

主要门：宏召回相对主视提高≥3个百分点，错误接受不增加，非法安全升级0，投影P95≤3 px、配对P95≤50 ms、端到端P95≤1000 ms，同时满足场景和部署条件。单物块离线数据不能完成整盘／机械验收。

## 8. 输出与控制

主视真实深度负责抓取；侧视不升级DEPTH_INVALID／NO_GRASP_SURFACE／OCCLUDED。控制结合health、互锁、PICKABLE、selected和位姿。详见[结果字段](RGB-D结果颜色与字段说明.md)及[服务接口](服务接口与部署.md)。
