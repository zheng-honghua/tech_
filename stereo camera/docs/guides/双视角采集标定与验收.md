# 双视角采集、标定与验收

## 1. 安全边界

双视角链路使用俯视 D435if RGB-D 作为唯一的实例数量、深度、三维坐标和抓取位姿来源，侧置 UVC RGB 只提供形状类别证据。任何侧视结果都不能把 `DEPTH_INVALID`、`OCCLUDED`、`NO_GRASP_SURFACE` 或 `DEPTH_REQUIRED` 升级为 `PICKABLE`。控制端仍必须同时检查整帧 `health.ok=true`、对象 `status=PICKABLE` 和 `selected=true`。

双视角默认关闭。只有显式传入 `--source dual` 才启动侧相机与融合；单目命令、JSON schema v2 和原控制字段保持兼容。

## 2. 安装与平台配置

安装 RealSense、双视角标定和测试依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,realsense,dual]"
```

俯视相机尽量垂直料盘并保留 10%–15% 余量。侧相机以约 35°–50° 俯角朝向料盘中心。两机和料盘必须有刚性支架/定位挡块；扎带只能用于临时流程验证。固定曝光、白平衡和焦距，并使用漫反射照明。

`config/dual/temporary.yaml` 和 `config/dual/competition.yaml` 分开保存平台 ID 与文件入口。切换比赛平台后必须重新采集标定和空盘，不能复制临时平台的像素 ROI、外参或颜色阈值。

## 3. 成对采集

需要人工逐类拍摄、同时查看俯视 RGB/深度和侧视 RGB 时，推荐使用带质量门与断点续拍的独立程序；完整按键和文件说明见[三 AprilTag 双相机采集与标定程序](三AprilTag双相机采集与标定程序.md)：

```powershell
.\.venv\Scripts\python.exe scripts\dual_rgbd_side_capture.py `
  --dataset-root data\dual --batch-id temporary-01 --platform-id temporary `
  --side-camera-index 1 --start-label empty_tray --target-per-label 10
```

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli dual-capture `
  --dataset-root data\dual --batch-id temporary-01 --platform-id temporary `
  --side-camera-index 1 --label cube --count 10
```

空盘批次可增加 `--side-background-output config\dual\temporary\side-background.png`，命令会保存已通过同步门槛的侧帧中位图。切换支架、焦距、曝光、照明或料盘位置后必须重拍。

有界缓存用主机单调时钟配对，设备时间戳同时保存在样本元数据。配对差超过 50 ms 的帧不会保存为合格成对样本。每个样本包含 `primary-color.png`、`primary-depth.npy`、`side-color.png` 和 `metadata.json`，后者记录双帧 ID、设备/主机时间戳、配对误差、主相机内参、平台 ID、标定哈希、标签和人工审查状态。

临时平台每类建议约 10 个成对姿态，并拍至少 15 个多物体场景，只验证流程。比赛平台每类建议 30 个姿态，按 20 训练、5 概率标定、5 不同批次最终留出；另拍 20 个调试和 20 个最终验收多物体场景。

## 4. ChArUco 标定

若使用用户指定的“三个 AprilTag：两个对角固定、一个自由移动/旋转”方式，可改用实时独立程序。它会保留每对原始帧与时间戳，并输出与融合链路兼容的标定 JSON：

```powershell
.\.venv\Scripts\python.exe scripts\dual_apriltag_calibrate.py `
  --platform-id temporary --side-camera-index 1 --tag-size-mm 30 `
  --fixed-tag-inset-mm 20 --required-poses 20 `
  --output config\dual\temporary\calibration.json
```

具体打印尺寸、两个固定标签的同向摆法、按键顺序和验收规则见[三 AprilTag 双相机采集与标定程序](三AprilTag双相机采集与标定程序.md)。下方 ChArUco 仍作为原有替代标定入口保留。

两相机同步拍摄至少 20 个覆盖画面、姿态不同的 ChArUco 图；其中至少 15 对必须有 6 个以上共同角点。两个目录使用同名文件，或保证排序后严格一一对应。

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli dual-calibrate `
  --primary-dir data\dual-calibration\primary `
  --side-dir data\dual-calibration\side `
  --background-dir data\empty-tray-rgbd `
  --platform-id temporary --squares-x 7 --squares-y 5 `
  --square-length-mm 20 --marker-length-mm 14 `
  --tray-pose-index 19 `
  --output config\dual\temporary\calibration.json
```

`--tray-pose-index` 是排序后的零基成对图索引，该帧的标定板必须平放并固定在料盘内。它建立料盘坐标系的原点和方向；`--background-dir` 同时用空盘深度拟合料盘平面。命令会把 `T_tray_from_primary` 和深度平面一同写入标定文件。运行时若该平面与当前 RGB-D 工作空间偏差超过 3 mm 或 3°，禁止融合。

标定文件带 SHA-256 内容哈希。运行时只接受：两机单目标定 RMS 均不超过 0.8 px、共同角点对称极线误差 P95 不超过 3 px、三角化标定板尺度中位误差不超过 1%。平台 ID、图像尺寸或哈希不匹配时返回 `CALIBRATION_INVALID`，禁止融合。

主相机的料盘平面和机械外参仍由 `rgbd-calibrate` 单独生成。标定板平放料盘时可核对坐标，但侧视标定文件不会替代 RGB-D 到机器人的变换。

## 5. 侧视模型与运行

侧视模型使用独立侧视数据，仍可复用 `geometry-train` 的 OpenCV 几何模型接口：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli geometry-train `
  --data-root data\dual-side-train --feature-set edge-topology `
  --output models\side-geometry.npz
```

运行时俯视实例点云连同其料盘平面投影构成三维包围体，再投影到侧相机形成一对一 ROI，不按颜色或全图最近目标匹配。两个投影 ROI 对较小 ROI 的覆盖超过 30% 时，两者都标为 `SIDE_OCCLUDED`。侧视背景差分、清晰度、面积和投影可见率共同产生质量 `q`；只有 `q≥0.60` 才融合。

融合采用温度标定后的完整类别概率。侧视权重为 `0.30×q`，余下权重归俯视。双方最高概率均至少 0.75 且类别不同则 `CONFLICT` 并拒识。融合最高概率至少 0.72、前两类差至少 0.12 才接受。俯视距离拒识不能被侧视升级；只有俯视类别间隔拒识才允许在俯视前两候选中消歧。

每类5个概率标定样本应写为 `split=probability_calibration`，并提供人工真值及 `top_class_scores`、`side_class_scores`。用独立命令拟合温度，再把结果写入对应平台配置的 `top_temperature` 和 `side_temperature`；禁止在最终留出集上反向调参：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli dual-temperature-fit `
  --records output\competition-probability-calibration.jsonl `
  --output output\dual-temperature.json
```

侧机缺失、模糊、遮挡、不同步或标定无效时，只有俯视形状概率至少 0.85 且全部 RGB-D 安全条件已满足，才保留单目 `PICKABLE`。

## 6. 联系表与人工审查

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli dual-review `
  --samples-root data\dual\temporary\temporary-01 `
  --output-dir output\dual-review-temporary-01 `
  --platform-id temporary `
  --rgbd-calibration config\rgbd-calibration.json `
  --dual-calibration config\dual\temporary\calibration.json `
  --side-background config\dual\temporary\side-background.png `
  --side-shape-model models\side-geometry.npz
```

命令先复放每个成对样本，在俯视图绘制实例结果、在侧视图绘制投影 ROI 和融合状态，再生成俯视 RGB、侧视 RGB、对齐深度三联联系表和 `dual-review-manifest.json`。可用 `--background-dir` 代替 `--rgbd-calibration`。生成不等于审查完成；必须实际打开每张联系表，检查投影 ROI、遮挡/错配、反光、阴影、深度孔洞、合并/拆分及类别冲突，并把具体批次、帧 ID 和结论写进报告。正式样本的 `human_reviewed` 必须由人工复审流程更新。

## 7. 推广门槛

`dual-evaluate` 读取 JSONL，每条应包含 `split`、`human_reviewed`、`platform_id`、真值、单目/融合标签和接受状态，以及投影误差、配对误差、端到端时延和安全状态升级标记：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli dual-evaluate `
  --records output\competition-final-holdout.jsonl `
  --output output\dual-promotion-report.json
```

只有人工复审过的 `final_holdout` 比赛平台记录参与。所有条件必须同时通过：融合宏召回比单目至少高 3 个百分点；错误接受率不升高；安全状态升级为零；投影误差 P95≤3 px；配对误差 P95≤50 ms；端到端 P95≤1000 ms。未通过时可保留诊断输出，但正式运行继续使用单目稳定链路。
