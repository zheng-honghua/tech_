# 环境、PowerShell与相机排错

更新：2026-10-02。你已经接上侧相机，原来的打开错误消失。下面保留完整定位步骤，供后续重启、拔插和换机使用。

## 1. 工作目录与环境是两件事

```powershell
Set-Location "C:\Users\d114\Desktop\tech_\stereo camera"
Get-Location
.\.venv\Scripts\python.exe `
    -c "import sys, sorting_vision; print(sys.executable); print(sorting_vision.__file__)"
.\.venv\Scripts\python.exe -m pip check
```

路径应分别指向双相机工程、双相机`.venv`和双相机`src`。`(.venv)`不保证上述三者正确。工作区根目录和两个子工程都有可能存在环境，不能混用。

如果Python可运行但包路径指向另一个工程，在双相机根目录重新绑定：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,realsense,dual]"
```

若`.venv`不存在才创建；已有环境移机后失效时新建独立环境并安装，不把别的目录`.venv`直接复制过来。

## 2. 正确复制PowerShell命令

- `PS C:\...>`和`>>`是提示符，不属于命令。
- 优先复制教程的单行命令。
- 多行命令的续行符是行尾反引号；其后不能有空格或注释。
- 最后一行不加续行符。误入等待状态按`Ctrl+C`取消，再完整粘贴。
- 路径含空格要加引号；调用带引号的可执行路径使用`&`。
- CLI的`--config`在子命令前；脚本的`--config`在脚本名后。

可选激活只影响后续`python`，不会切换目录：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
& ".\.venv\Scripts\Activate.ps1"
```

## 3. 侧相机打不开的顺序

1. 确认侧相机实际接入、线缆可靠；等Windows识别完成。
2. 关闭Windows相机、RealSense Viewer、会议软件、旧采集和标定窗口。
3. 保持当前DSHOW／1280×720／30 FPS设置，先试配置的索引。
4. 失败时依次试其他索引；每次结束前一个程序，不并行打开。
5. 成功后确认画面确实是侧面视角，并记录设备和索引。

```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli `
    --config config\dual\temporary.yaml camera-live `
    --source uvc `
    --camera-index 1 `
    --width 1280 `
    --height 720 `
    --fps 30
```

把上面的`1`分别改为`0`、`2`、`3`逐条尝试。能打开某个索引不代表它就是侧相机。错误里的DSHOW提示表示该次打开失败，无法单凭这一行区分未接入、索引、占用和驱动。

Windows设备名称可辅助核对，但名称列表顺序不等于OpenCV索引：

```powershell
Get-PnpDevice -PresentOnly | Where-Object { $_.Class -in @("Camera", "Image") } | Select-Object Status,Class,FriendlyName
```

设备管理器中确认设备状态；Windows“隐私和安全性→相机”允许桌面应用访问。仍失败时再检查USB口、线缆和驱动，不盲目改算法门槛。

## 4. RealSense打不开或档位不支持

主相机使用RealSense SDK，不靠侧机`--camera-index`。先关闭占用软件，单独打开主机。`Couldn't resolve requests`通常表示请求的流组合不支持；在Viewer中确认可用分辨率／FPS后关闭Viewer再运行工程。

临时配置请求主RGB1920×1080／15 FPS和深度848×480／15 FPS。改档位后重新核对对齐、内参、同步、背景与数据分布。更高RGB分辨率不会增加原生深度采样数量。

`No device connected`先处理USB／供电／设备识别；`ModuleNotFoundError: pyrealsense2`先安装本工程`.[realsense]`。

## 5. 黑屏、亮度变化与读帧失败

先区分无图像和低亮度。历史临时侧机强制手动曝光`-6`曾导致黑屏或读帧失败，因此当前配置使用自动曝光与自动白平衡。不要照抄其他相机曝光值。

让照明稳定、等待自动模式收敛；固定支架与焦距模式。驱动不支持某个设置时记录实际行为。锁定曝光／白平衡应在设备支持且实拍检查后进行，并重采背景和校准数据。

## 6. 采集助手始终WAIT

| 原因 | 处理 |
|---|---|
| 主／侧画面运动 | 移走手、固定支架，等连续稳定帧 |
| 有效深度低 | 看原深度、反光、工作距离和取景，不能只看RGB |
| RGB-D同步差 | 核对主机流配置、负载和时间戳 |
| 两机配对差过大 | 核对侧流、USB负载，关闭其他负载程序 |
| 侧图模糊 | 检查镜头、焦距、光照和运动 |
| 当前批次没有空盘 | 先切`0`保存空盘 |

`READY`是采集质量门，不是标定、标签、实例分离或抓取验收。`F`保留异常诊断并记录覆盖，不能代替正常采集。

## 7. 标定和模型错误

| 错误 | 正确定位 |
|---|---|
| `calibration hash mismatch` | 元数据绑定原采集几何；找对应原文件或重采新平台数据 |
| 图像尺寸不一致 | 运行档位、裁剪、内参和原生尺寸统一 |
| `CALIBRATION_INVALID` | 看投影、尺度、料盘平面、平台及质量profile |
| 模型／特征指纹不一致 | 选配套配置和模型，重新提取／拟合新语义 |
| 找不到v8颜色文件／模型 | 先检查v8产物依赖；普通temporary没有这些实验模型 |
| 大量unknown | 看distance／margin／冲突；不要把所有拒识理解为相机没拍到 |

历史采集哈希与开发标定不同的回放只作开发证据；新实拍要绑定当前有效标定。不要直接编辑哈希使检查通过。

## 8. 求助时保留的信息

保留完整命令、当前目录、Python路径、报错末尾、两台设备名称、分辨率／FPS、配置路径、批次ID及一组完整样本路径。不要仅截取绿色框或最后一行报错。这样可以区分环境、采集、几何与分类问题。
