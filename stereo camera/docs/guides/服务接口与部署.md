# 服务接口、运动互锁与部署

更新：2026-10-02。视觉服务输出判定，不负责发送机器人运动命令。硬件、外参和模型未验收时先离线回放或本地诊断。

## 1. JSON/TCP消息格式

服务使用UTF-8、一行一个JSON、以换行结束。保持连接后可发送多个请求；每个响应同样以换行分隔。

支持type：health、detect、motion_start、motion_stop、ack_pick。request_id用于关联响应。

```json
{"type":"health","request_id":"check-1"}
{"type":"detect","request_id":"detect-1"}
```

代码入口server.py的VisionService3D.handle；结果使用schema_version=2。未知请求的返回以服务代码为准，控制端必须处理错误与空结果。

## 3. 客户端只读联通检查

在另一个终端运行；此示例只请求health：

```python
import json
import socket

with socket.create_connection(("127.0.0.1", 8765), timeout=5) as connection:
    connection.settimeout(5)
    connection.sendall((json.dumps({"type": "health", "request_id": "check-1"}) + "\n").encode("utf-8"))
    with connection.makefile("r", encoding="utf-8") as stream:
        print(json.loads(stream.readline()))
```

可以保存为自己的client_health.py，在服务启动后用本工程Python运行。单次recv不保证读取完整消息，应按换行读完整响应。这里只验证TCP，不验证相机、标定或运动。

## 4. 状态与互锁

motion_start表示控制端已经开始运动，服务进入运动锁并清空跟踪结果；motion_stop表示运动已结束，仍需画面稳定后才恢复计算。它们不是“让机器人开始／停止”的执行指令。

ack_pick用于外部确认一次抓取已完成后清除／更新选择状态；只有实际完成后发送，不用它伪造成功。detect更新采集和结果；health读取当前状态，不能代替持续采集检查。

控制端应同时检查：
- health.ok、health.can_pick、run_state与camera_error。
- 对象status=PICKABLE、selected=true。
- pose_3d／grasp完整、坐标系和实际机械外参正确。
- 当前目标、帧ID、时效及外部机械互锁条件。

RGB_ONLY固定不可执行，RGBD／RGBD_DUAL也必须满足全部真实深度与抓取条件。识别出形状名、FUSED或绿色显示框不单独授权。

## 5. 部署配置

新设备建立自己的配置，保存相机型号、档位、内参／双机／机械外参、空盘、背景、模型契约与路径。不要复制临时平台的像素ROI和旧哈希充当新标定。

默认绑定127.0.0.1先做本机测试；需要跨机器时按现场网络配置host／port，并核对连接失败、断线、重复消息和超时处理。服务未实现通用机器人协议，集成时保留控制端校验。

## 6. 性能与验收

记录冷启动／预热、线程数、分辨率、输入规模和目标设备。离线应用P95通常不含相机采集、读图、绘图、网络与机械；现场端到端另计。

模型后端在目标机比较类别、完整概率和接受口径；详细见[训练与后端](模型训练与后端.md)。接口字段与状态见[结果说明](RGB-D结果颜色与字段说明.md)。
