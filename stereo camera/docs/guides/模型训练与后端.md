# 模型训练、校准与后端使用

更新：2026-10-02。所有新模型先保存到experimental或独立output目录。先明确输入格式、拟合／校准／测试隔离和特征契约，再训练。

## 1. 选对训练器

| 命令／脚本 | 输入 | 结果与限制 |
|---|---|---|
| geometry-train | 按形状文件夹组织的RGB图片 | RGB几何模型；没有深度 |
| geometry-rgbd-train | 单RGB-D样本，color/depth/metadata | 主视点云几何模型；不是双相机四文件训练器 |
| dual-side-train | 经审查的双机配对样本＋背景 | 侧视KNN／RTrees，按split隔离校准 |
| dual-fusion-fit | 已审probability_calibration完整概率记录 | 温度、Top-2融合与接受策略 |
| train_dual_fusion_holdout.py | 配对数据＋对应标定，批次×形状内部留出 | 历史开发三模型训练；最终会将内部校准并回拟合 |
| experiment_color_ridge_v7.py | 冻结历史ID和已有来源 | v7实验，分阶段prepare/extract/fit |
| experiment_color_geometry_v8.py | v6旧观测／快照＋v7既有颜色 | v8冻结实验重拟合，非任意新照片训练器 |

## 2. 数据与输出目录

训练用train，校准用probability_calibration，最终评估用final_holdout。RGB／主RGB-D通用训练器不会自动按双机metadata的split替你筛选，须传独立训练目录／明确batch-id。

不要用已查看的108开发回归反复调门槛后称它为独立最终测试。不要用校准数据拟合模型后继续引用原校准误差。

新输出示例：models/experimental/new-batch-20261002/，不要覆盖默认或v6/v7/v8。

## 3. RGB几何模型

输入目录每个文件夹一个形状，文件为RGB照片。先审计，再训练：

```powershell
Set-Location "C:\Users\d114\Desktop\tech_\stereo camera"
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli geometry-audit `
    --data-root data\rgb-train `
    --output-report output\rgb-train-audit-20261002.json
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli geometry-train `
    --data-root data\rgb-train `
    --feature-set edge-topology `
    --output models\experimental\rgb-candidate-20261002.npz `
    --output-report output\rgb-training-20261002.json
```

legacy、edge-topology、structure-topology语义不同，模型与推理必须一致。输入目录示例需由你实际准备。预测见[单图教程](单图预测使用说明.md)。

## 4. 主RGB-D模型

用单相机采集命令得到color.png、depth.npy、metadata.json，详细流程见[RGB-D采集训练](RGBD数据采集与训练.md)。--strict-single-object拒绝多实例，--fused-edges启用对应内部线特征，baseline-output输出同样本对照。

这些选项不会自动生成v6完整双掩膜语义。新双机主模型需核对完整输入契约，不拿普通RGB-D模型替代legacy完整HSV模型。

## 5. 侧视独立训练

准备经实际查看的配对样本，metadata有train与probability_calibration；背景对应同一平台。

```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli dual-side-train `
    --samples-root data\dual\temporary `
    --side-background config\dual\temporary\side-background.png `
    --shape-registry config\shapes\competition-11.yaml `
    --output models\experimental\side-candidate-20261002.npz `
    --report output\side-training-20261002.json
```

该命令比较KNN／RTrees，优先错误接受为零，再看宏召回、覆盖和时延。默认要求human_reviewed；--allow-unreviewed仅开发例外，报告必须披露，不能把未审资料视为正式验收。

模型保存类别顺序、注册表和特征指纹。缺类／加载错误要看load_errors及audit，不按有效子集隐去失败分母。

## 6. 融合策略校准

需要每条记录有split=probability_calibration、human_reviewed、true_label、top_class_scores、side_class_scores，以及真实side_quality。概率向量包含同一注册表的完整类别，不是只有预测标签。

```json
{"split":"probability_calibration","human_reviewed":true,"true_label":"cone","top_class_scores":{"cone":0.6,"hexagonal_pyramid":0.4},"side_class_scores":{"cone":0.7,"hexagonal_pyramid":0.3},"side_quality":0.8}
```

上例只演示字段结构；实际记录使用全部启用类别和真实模型概率，不能复制示例数值作为校准数据。

```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli dual-fusion-fit `
    --records output\new-probability-calibration.jsonl `
    --shape-registry config\shapes\competition-11.yaml `
    --output models\experimental\fusion-candidate-20261002.json `
    --report output\fusion-fit-20261002.json
```

只拟合温度可用dual-temperature-fit；完整fusion-fit同时选择策略。最终记录报告的接受覆盖、错误接受和拒识，冻结后再评价测试集。

## 7. 历史三模型开发脚本的边界

train_dual_fusion_holdout.py内部按batch×shape留出，并提取主、侧、联合模型。它沿用历史最终重拟合方式，会把内部校准加入最终拟合；不满足v7/v8“校准永不回并”的新实验要求。

因此新正式实验应显式采用隔离的模型拟合与策略校准；不能只运行旧脚本并宣称348/72隔离。参数清单和固定数据来源见[CLI索引](CLI命令与参数索引.md)及[v6报告](../reports/完整色块双视角v6重训与固定回归_20260918.md)。

v8支持从旧观测快照重拟合并核验来源，应用回放仍需原照片；颜色原型来自既有拟合集，新增黑／浅蓝实拍不自动进入这些旧原型。

## 8. 特征与模型契约

记录visual_version、mask/ridge指纹、shape_input_contract、registry_hash、输入分辨率和训练ID。重新改变分割、线段来源、合并规则或面语义时重新提取并拟合匹配模型；不关闭兼容检查。

v8三套形状模型保留legacy，v7颜色／棱线诊断独立。颜色恢复或验证图不能偷偷改变旧形状向量。模型加载成功也要做实际应用回放和视觉审查。

## 9. 可选CNN和部署后端

当前颜色／棱线优化路线仍是经典视觉；CNN为已有可选实验。

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[cnn-train]"
.\.venv\Scripts\python.exe -m sorting_vision.cli geometry-cnn-train --help
.\.venv\Scripts\python.exe -m sorting_vision.cli geometry-cnn-export --help
.\.venv\Scripts\python.exe -m sorting_vision.cli dual-side-cnn-train --help
.\.venv\Scripts\python.exe -m sorting_vision.cli dual-side-cnn-export --help
.\.venv\Scripts\python.exe -m sorting_vision.cli dual-side-backend-check --help
```

OpenVINO推理安装.[cnn]。TensorRT引擎在目标Orin生成，不能将Windows上的导出或耗时当作Orin验收。不同后端不仅比较类别，还比较接受／拒识口径、完整概率、P95和安全状态。

## 10. 必须保留的交付

训练ID、校准ID、测试ID与失败ID；原始来源哈希；配置／代码／特征版本；模型／策略；实际看图记录；含unknown的正确率／宏召回、错误接受、覆盖与P95；完整应用安全状态。期望改进与实测改进分开写，未通过保持promotion_eligible=false。
