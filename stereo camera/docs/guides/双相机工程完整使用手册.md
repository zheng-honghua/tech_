# 双相机工程完整使用手册

更新：2026-10-02。面向当前Windows／PowerShell工作区。主相机采集RGB和真实深度，侧相机采集RGB；两路共同帮助分类、棱线验证和空间对应。

## 1. 你现在到哪一步了

此前终端有两个独立问题：在`tech_`目录运行双相机脚本会找不到文件；进入正确目录后，侧相机未接好时索引`1`无法打开。你已经接上另一台相机，启动错误已消失。现在从“确认三画面→拍空盘→拍5–10组试样→检查文件”继续。

相机能打开只证明采集入口可用。标定、图深对齐、深度质量和模型准确率需要后面的检查分别确认。

## 3. 每次打开终端后的第一步

复制完整命令行，不复制终端提示符：

```powershell
Set-Location "C:\Users\d114\Desktop\tech_\stereo camera"
Get-Location
Test-Path .\pyproject.toml
Test-Path .\.venv\Scripts\python.exe
Test-Path .\scripts\dual_rgbd_side_capture.py
.\.venv\Scripts\python.exe `
    -c "import sys, sorting_vision; print(sys.executable); print(sorting_vision.__file__)"
```

应看到双相机目录，三个`Test-Path`均为`True`，Python路径位于该目录的`.venv`，包路径位于该目录的`src\sorting_vision`。如果包指向单目工程，先按[环境排错](环境与相机排错.md)修复可编辑安装。

后文显式使用`.\.venv\Scripts\python.exe`，无需反复激活。只有希望直接输入`python`时才可选用：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
& ".\.venv\Scripts\Activate.ps1"
```

当前窗口的执行策略设置不必每条命令都重复。终端关闭后重新核对路径即可。

```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli rgbd-demo `

```

第一次安装或缺少依赖时：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,realsense,dual]"
```

`dual`额外依赖组当前为空；AprilTag来自本工程的`opencv-contrib-python`。不要把多个OpenCV发行包混装成一个环境。CNN依赖仅在实际需要相应实验时安装，见[模型训练与后端](模型训练与后端.md)。

`rgbd-demo`成功只能验证软件接口与合成处理，不代表实拍效果或机器人坐标正确。

## 5. 固定采集配置与设备

当前临时平台配置为`config\dual\temporary.yaml`：

| 流 | 请求档位 | 说明 |
|---|---|---|
| 主RGB | 1920×1080，15 FPS | 颜色、轮廓、原生像素坐标 |
| 主深度 | 848×480，15 FPS | SDK对齐后保存到主RGB坐标 |
| 侧RGB | 1280×720，30 FPS | DSHOW／NV12，实际支持档位以设备为准 |

深度对齐后的数组可能为1920×1080，但原生深度信息仍来自848×480。预览块状不能直接解释为失焦。索引`1`是当前配置值；拔插、重启或增加摄像头后要重新确认画面。

先单独预览侧相机；结束窗口后再开下一条：

```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli `
    --config config\dual\temporary.yaml camera-live `
    --source uvc `
    --camera-index 1 `
    --width 1280 `
    --height 720 `
    --fps 30
```

确认它显示侧面视角，而不是RealSense RGB或笔记本内置相机。预览按`Q`退出。若失败，只逐次改变`--camera-index`，详细步骤见[环境与相机排错](环境与相机排错.md)。RealSense使用SDK打开，不依赖UVC的索引。

单独预览主相机：

```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli `
    --config config\dual\temporary.yaml camera-live `
    --source realsense `
    --color-width 1920 `
    --color-height 1080 `
    --depth-width 848 `
    --depth-height 480 `
    --fps 15
```

该入口是识别预览，其健康状态还受标定影响；实际RGB／深度／侧RGB三画面使用下一节采集助手。Windows相机、Viewer、标定和采集程序依次运行，每次关闭前一个释放设备。

## 6. 先拍一个独立试拍批次

此命令每个形状的计数目标为5，不会自动替你移动物块，也不会在5张后自动退出：

```powershell
.\.venv\Scripts\python.exe scripts\dual_rgbd_side_capture.py `
    --config config\dual\temporary.yaml `
    --dataset-root data\dual `
    --platform-id temporary `
    --batch-id pilot-blue-20261002 `
    --side-camera-index 1 `
    --color-width 1920 `
    --color-height 1080 `
    --depth-width 848 `
    --depth-height 480 `
    --fps 15 `
    --side-width 1280 `
    --side-height 720 `
    --side-fps 30 `
    --split train `
    --instance-id blue-set-01 `
    --color-id blue `
    --start-label empty_tray `
    --target-per-label 5
```

`blue`是新样本标准拼写。历史`bule`照片保持原记录；部分颜色实验读取时作兼容映射，不要在旧批次中混改颜色、实体或数据划分。

操作：

1. 清空料盘，等待图像亮度与深度稳定。
2. 看三画面是否来自正确相机、图深轮廓是否对应。
3. 选`0 / empty_tray`，等`READY`，按空格保存空盘。
4. 放一个物块，手离开画面，按数字或`N/P`选真实形状。
5. 等`READY`，按空格保存。旋转或移动后再拍。
6. 拍5–10组不同摆放，按`Q`退出，阅读终端保存路径和计数。

`F`是强制保存诊断样本，会记录`quality_override=true`，不使坏数据变成合格数据。试拍优先用普通空格。

## 7. 按键、质量门与成功标志

| 按键／提示 | 作用 |
|---|---|
| `0–9` | 选择窗口列出的形状；编号以当前注册表为准 |
| `N / P` | 下一／上一形状，包含圆锥和圆柱 |
| `A` | 跳到计数尚未达到目标的类别 |
| 空格 | 通过质量检查后保存当前一组 |
| `F` | 强制保存并记录覆盖标记，侧视完全缺失仍不保存 |
| `Q` | 关闭程序并释放两台相机 |
| `WAIT` | 动态、深度、同步或侧图清晰度尚不满足 |
| `READY` | 当前采集质量门通过；不等于标定或分类已经验收 |

助手默认要求连续3帧稳定、有效深度率≥0.85、主RGB-D同步差≤20 ms、双机配对差≤50 ms、侧图模糊方差≥35。有效深度率是采集门的统计范围，不等于每个物块边缘都有有效深度。

每个物块批次先有空盘；保存成功终端输出`saved[...]`和样本绝对路径，磁盘出现下一节的文件。

## 8. 样本目录、真值与断点续拍

```text
data/dual/
  dual-manifest.jsonl
  temporary/
    pilot-blue-20261002/
      empty_tray/sample-0001/
      cone/sample-0001/
        primary-color.png
        primary-depth.npy
        side-color.png
        metadata.json
```

`primary-depth.npy`保存原始深度数值，用元数据中的深度比例转成毫米。不要拿彩色深度预览参与点云计算。

元数据保存主／侧帧ID、设备和主机时间戳、配对差、主相机内参、平台与标定哈希、标签、颜色、实体、`split`、质量门与审查标志。普通采集初始`human_reviewed=false`。

复用同一个批次ID可续拍，程序按平台＋批次读取清单中的计数。换实体、颜色、设置或划分时建新批次。不要只删除照片而留下清单中的计数记录。

## 9. 试拍后先检查，再扩大采集

```powershell
Get-ChildItem -LiteralPath data\dual\temporary\pilot-blue-20261002 -Recurse -Filter metadata.json | Select-Object FullName
.\.venv\Scripts\python.exe scripts\audit_dual_depth_quality.py `
    --dataset-root data\dual\temporary\pilot-blue-20261002 `
    --output-dir output\pilot-depth-audit-20261002
```

打开RGB原图、侧图和审查输出，检查空盘平面、孔洞、对齐、反光、遮挡、完整轮廓及错标签。空间标定未准备好时可先生成原始三联联系表，见[视觉审查](视觉审查流程.md)；`dual-review`还要求标定哈希和背景匹配。

若深度大面积无效或物块边缘与深度偏移，先修采集、距离、照明或标定。降低分类阈值不能修复这些问题。

## 10. 正式数据如何划分

| 字段 | 用途 | 可以做什么 |
|---|---|---|
| `train` | 拟合模型／颜色原型 | 提取特征和训练 |
| `probability_calibration` | 选择温度、概率与拒识门 | 校准策略；之后保持独立 |
| `final_holdout` | 冻结后的最终检查 | 仅评估，不能再据此调参 |
| `development / final_acceptance` | 多物块场景`scene_split` | 分别开发和场景验收 |

实体ID表示实际物块组，不是每次摆放的流水号。相邻帧或相同摆放连拍不能拆散到训练与测试。优先按实体和采集批次隔离；新灯光或新平台另建批次并重采标定和背景。

先补拒识较集中的圆锥、五／六棱锥，再补任务需要但现有数据缺失的圆柱、黑色、浅蓝和真实接触场景。数据量应按形状×实际颜色×姿态覆盖统计；没有实物的组合记录缺失，不伪造样本。

## 11. 标定顺序

依次完成两路RGB内参→双机外参和料盘坐标→主相机空盘深度平面→实际机器人外参→侧视背景。每一步文件用途不同。

| 文件 | 解决的问题 |
|---|---|
| `primary-intrinsics.json` | 主RGB像素与射线；RGB-D投影还须核对SDK几何 |
| `side-intrinsics.json` | 侧RGB像素与射线 |
| `calibration.json` | 双机变换、料盘坐标、哈希和质量 |
| 主RGB-D标定JSON | 空盘平面及主相机到机器人的变换 |
| `side-background.png` | 无物块侧视背景，用于分割 |

具体打印、实测尺寸、按键和验收见[标定教程](三AprilTag双相机采集与标定程序.md)。示例尺寸不能代替料盘和标签实测值。

目前历史临时标定只用于开发，严格投影／尺度门尚未通过。相机能启动后仍需在当前固定支架上验证。历史照片的标定哈希不能简单改成新文件哈希。

## 12. 背景采集

确认两路画面正确、清空料盘，再自动保存20对空盘并生成中位背景：

```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli `
    --config config\dual\temporary.yaml dual-capture `
    --dataset-root data\dual `
    --batch-id background-20261002 `
    --platform-id temporary `
    --label empty_tray `
    --count 20 `
    --side-camera-index 1 `
    --split train `
    --instance-id empty `
    --color-id none `
    --side-background-output output\background-20261002\side-background.png `
    --headless
```

此命令会自动拍摄，先检查取景。输出写到新目录，检查后在自己的候选配置中设置`side_background_path`。物块批次自己的空盘样本仍要拍，它与全局中位背景用途不同。

## 13. 视觉审查与训练

先用[审查流程](视觉审查流程.md)实际查看样本；再按[模型训练](模型训练与后端.md)选择RGB、主RGB-D、侧视或联合分支。

`geometry-train`读取单张RGB的类别文件夹；`geometry-rgbd-train`读取单相机RGB-D数据包；`dual-side-train`读取双相机配对数据及明确的训练／校准划分。它们不能互换输入目录。

新采集数据不能直接交给固定历史ID的v7/v8脚本就认为已经完成新批次训练。历史v8提供的是旧观测快照的可复现拟合。新数据的完整分割和三模型训练要单独建实验、核对特征契约、隔离校准，并重新审查。

## 14. v6、v7、v8如何选择

| 版本 | 主要用途 | 当前开发证据 |
|---|---|---|
| v6 | 稳定形状输入的历史基线 | 108组形状80正确、26拒识、2错类；旧颜色输出存在问题 |
| v7 | 两路颜色、原图棱线验证的实验 | 颜色改善；形状拒识、角点覆盖和耗时退化 |
| v8 | v6几何＋v7颜色／线验证分层组合 | 形状77正确、26拒识、5错类；保留诊断和回退 |

历史v6最终拟合420组，v8拟合348／校准72，两者不是同训练条件对照。三个版本均无比赛推广结论；`promotion_eligible=false`。正确形状名、可靠三维线和可抓状态分别统计。

复现见[v7](../v7颜色棱线实验复现.md)和[v8](../v8双相机融合实验复现.md)，实测结果见[报告](../reports/v6v7取长补短v8离线对照_20261001.md)。

## 15. 离线回放与实时预览

历史v8模型和原照片存在时，可把回放输出写到独立目录：

```powershell
.\.venv\Scripts\python.exe scripts\replay_dual_application.py `
    --run-dir output\dual-color-geometry-v8-20261001 `
    --config config\dual\temporary-color-geometry-v8.yaml `
    --output-dir output\v8-replay-20261002 `
    --show-side-edges `
    --show-sparse-geometry `
    --opencv-threads 2
```

`--run-dir`指定模型及冻结输入来源；`--output-dir`只改变本次回放输出。运行前检查依赖，缺照片或来源清单时按复现指南补齐。此命令不会采集新相机数据。

实时双视角识别需要有效主空盘标定或对应背景帧；完整命令模板见[验收教程](双视角采集标定与验收.md)。先确认当前几何、背景和模型匹配，再连接融合。

## 16. 看懂结果

二维候选线→图像验证线→几何三维候选→双路支持的确认棱线，是不同证据层。数量多不等于可靠程度高。圆锥、圆柱的曲线轮廓不能自动成为真实直棱或三维角点。

主视颜色作为最终颜色，侧视独立预测用于冲突否决。侧视不能补造抓取深度。`DEPTH_INVALID`、`NO_GRASP_SURFACE`和`UNCERTAIN`要分别查原因。

控制使用`schema_version=2`；需要健康状态、运动互锁和对象选择共同满足条件。完整字段及颜色图例见[结果说明](RGB-D结果颜色与字段说明.md)。

## 17. 每次拍摄与开发的收尾

1. 按`Q`退出并确认设备释放。
2. 记录平台、批次、实体、颜色、分辨率、照明及标定哈希。
3. 检查样本目录和清单；保存失败原因，不把失败帧从评估分母删掉。
4. 备份原始照片、原始深度、元数据、清单及标定。
5. 给训练、回放和审查使用不同输出目录。
6. 完成审查后再写明确的逐样本决定；不要批量设为已审。

## 18. 快速查错

| 现象 | 先检查 |
|---|---|
| 找不到脚本 | `Get-Location`是否是双相机目录 |
| `cannot open UVC camera index` | 侧机是否接好、是否占用、索引是否对应正确画面 |
| 黑屏／`Couldn't resolve requests` | 实际支持的档位、USB与曝光设置 |
| 始终`WAIT` | 动态、有效深度、配对差、侧图清晰度逐项看 |
| `capture empty_tray first` | 当前批次先保存空盘 |
| `calibration hash mismatch` | 使用原采集标定或为新平台重新采集 |
| `feature/model contract`错误 | 分割、特征语义、模型版本与注册表要匹配 |
| 检出物块但不可抓 | 查看health、深度、抓取面、稳定帧和selected |

逐项处理见[环境与相机排错](环境与相机排错.md)，不要同时更改索引、分辨率、曝光、标定和模型。
