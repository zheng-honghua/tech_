# 双视角形状与颜色数据采集完整教程

本文用于当前工程的双视角数据建设：俯视 Intel RealSense D435if 同时提供 RGB 和深度，侧置 USB 相机提供 RGB。它们是两台物理相机、三路数据，不是三台相机。

当前阶段先训练形状识别，但采集时必须同时记录物块的真实颜色。以后训练颜色识别时可以直接复用同一批照片，不需要重新把“红色三棱柱”“绿色三棱柱”做成不同形状类别。

## 1. 先理解五个字段

每一张单物块样本都包含以下信息：

| 字段 | 示例 | 含义 |
|---|---|---|
| `label_id` | `triangular_prism` | 形状真值，参与11类形状训练 |
| `color_id` | `red` | 颜色真值，供颜色训练和分层评测使用 |
| `instance_id` | `A` | 实体编号，用于防止同一个实体泄漏到最终测试集 |
| `split` | `train` | 数据用途：训练、概率校准或最终留出 |
| `batch_id` | `train-A-red-20260915` | 本次拍摄批次的唯一名称 |

正确方式：

```text
shape/label_id = triangular_prism
color_id       = red
```

错误方式：

```text
label_id = red_triangular_prism
```

最终识别程序应独立输出形状和颜色，再在业务层组合：

```json
{
  "shape_id": "triangular_prism",
  "shape_confidence": 0.91,
  "color_id": "red",
  "color_confidence": 0.96
}
```

这样可以避免把11种形状和5种颜色扩展成55个组合类别，也能降低颜色与形状错误绑定导致的过拟合。

## 3. 正式采集前先锁定比赛颜色表

当前基础配置中有六个候选颜色 ID：

```text
red     红色
yellow  黄色
blue    蓝色
green   绿色
black   黑色
cyan    浅蓝色
```

既定数据验收规则要求每种形状覆盖五种比赛颜色，因此正式采集前必须确认比赛实际使用哪五种。只从上面选择真实存在的五种，并在全部批次中使用完全相同的英文 ID。

例如 `red` 和 `红色` 会被数据审计视为两个不同字符串，不能混用。没有实物的颜色不能为了凑数量伪造数据。如果比赛实际不是五种颜色，应先修改数据目标和审计规则，再开始正式采集。

## 6. 当前已经确认的三路拍摄参数

临时平台配置 `config/dual/temporary.yaml` 当前使用：

| 数据流 | 分辨率 | 帧率 | 用途 |
|---|---:|---:|---|
| 俯视 RGB | 1920×1080 | 15 FPS | 颜色、轮廓、显示 |

只要改变以下任意项目，就要重新核对或重做标定：

- 相机或料盘位置；
- 相机角度或支架；
- 镜头焦距；
- RGB 分辨率；
- 图像发生裁切、缩放或防抖；
- 更换相机设备。

单纯改变帧率通常不改变内参，但会改变带宽、曝光和同步表现，仍需重新做同步与图像质量测试。

## 7. 每次拍摄前的现场检查

开始一批数据前逐项检查：

1. 两台相机、料盘和支架均不能晃动。
2. 俯视 RGB 中必须完整看到料盘，四周保留约10%–15%余量。
3. 侧视 RGB 中必须完整看到料盘，并能看到物块侧面。
4. 俯视深度中的料盘区域不能大面积为黑色无效值。
5. 画面内不要留下手、标定板、AprilTag、工具、线缆和其他物体。
6. 灯光位置和亮度在同一平台数据中保持一致。
7. 白色料盘上不能有很强的移动阴影或过曝区域。
8. 物块放稳、手完全移出画面后再等待 `READY`。
9. 不要同时打开 RealSense Viewer、Windows 相机或其他占用设备的软件。
10. 确保磁盘有足够空间，并定期备份 `data/dual` 和 `dual-manifest.jsonl`。

临时平台当前允许自动曝光和自动白平衡，拍摄前应等待亮度稳定。比赛正式采集更推荐在调好灯光后锁定曝光、白平衡和焦距，并用同样设置重拍标定与背景。

侧视分割需要一张没有物块的背景图。清空料盘，确认三路画面正常后运行：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli `
  --config config\dual\temporary.yaml `

  --dataset-root data\dual `
  --batch-id temporary-background-20260915 `

  --color-width 1920 --color-height 1080 `
  --depth-width 848 --depth-height 480 `
  --fps 15 `
  --side-width 1280 --side-height 720 --side-fps 30 `
  --split train `

  --color-id none `
  --side-background-output config\dual\temporary\side-background.png `
  --headless
```

`--headless` 会在没有预览窗口的情况下自动保存20对同步空盘帧并生成中位背景。运行前必须先用三画面助手确认取景正确；否则它可能把错误画面自动保存完。

完成后确认文件存在：

```powershell
Test-Path config\dual\temporary\side-background.png
```

应输出：

```text

```

注意：全局 `side-background.png` 用于背景差分；采集助手要求“当前物块批次先有一张空盘样本”用于保证批次完整性。这是两个不同用途，不能互相替代。

## 10. 三画面和状态文字怎么判断

窗口顶部依次显示：

```text
TOP RGB | TOP DEPTH | SIDE RGB
```

状态示例：

```text
READY | label [0] empty_tray | saved 0/5
depth 97.8% | RGB-D 0.0 ms | pair 4.3 ms
motion top/side 0.72/0.48 | side blur 458.0
```

各项含义：

| 状态 | 当前默认合格条件 | 含义 |
|---|---:|---|
| `READY` | 所有质量门均通过 | 可以按空格保存 |
| `depth` | ≥85% | 整幅深度有效像素比例 |
| `RGB-D` | ≤20 ms | D435if 彩色与深度时间差 |
| `pair` | ≤50 ms | 俯视与侧视帧时间差 |
| `motion top/side` | 连续3帧均≤2.5 | 相机、物块和手已基本停止 |
| `side blur` | ≥35 | 侧视清晰度指标，越高通常越清晰 |

截图中的 `depth 97.8%`、`RGB-D 0.0 ms`、`pair 4.3 ms`、`side blur 458.0` 和绿色 `READY` 均通过当前门槛。

这些数值通过不等于标签一定正确。保存前仍要由人确认物块类别、颜色、实体编号、遮挡和取景。

## 11. 按键说明

| 按键 | 功能 | 使用要求 |
|---|---|---|
| `Space` | 保存当前样本 | 只在绿色 `READY` 且真值正确时使用 |
| `0–9` | 直接选择编号0–9 | 10、11类不能用两位数字直接输入 |
| `N` | 下一类别 | 可进入圆锥和圆柱体 |
| `P` | 上一类别 | 用于回退检查 |
| `A` | 跳到下一个未完成类别 | 正常逐类采集推荐使用 |
| `F` | 绕过质量门强制保存 | 正式训练、校准和最终留出禁止使用 |
| `Q` | 安全退出 | 中断后可用相同批次继续 |

## 12. 每个批次的正确拍摄顺序

每个新批次按以下顺序操作：

1. 保持空盘，等待绿色 `READY`。
2. 按一次 `Space` 保存当前批次的空盘样本。
3. 按 `A` 或 `N` 进入第一种形状。
4. 放入界面所示形状、当前命令所示实体和颜色的物块。
5. 手完全移出，物块停止，等待绿色 `READY`。
6. 再次核对三路画面和真实标签，然后按 `Space`。
7. 改变稳定面、旋转角度和盘内位置，重复到目标数量。
8. 按 `A` 进入下一种未完成形状。
9. 完成11种形状后按 `Q`。

空盘只需至少一张即可解除当前批次的保存门。由于 `--target-per-label` 同时显示为空盘目标，空盘未达到例如 `5/5` 不会妨碍手动进入其他类别；完成物块后直接按 `Q` 即可。需要更丰富的空盘变化时可以额外拍摄，但空盘中不能出现手或物块。

## 13. 单个物块应该怎样改变姿态

同一类别的多张样本必须包含真实变化，而不是连续复制几乎相同的画面。优先覆盖：

- 盘内中心、四角和边缘附近的位置；
- 绕竖直轴的不同旋转角度；
- 实物允许的不同稳定面；
- 侧面棱线清楚和较弱的情况；
- 俯视轮廓相近、但侧视轮廓不同的困难姿态；
- 不同日期或允许范围内的轻微照明变化。

每次摆放建议至少明显改变一项。不要把同一静止摆放连续拍5张当作5个独立样本；这种数据会造成虚高的训练结果和严重过拟合。

单物块采集时不要：

- 让第二个物块进入料盘；
- 用手扶住物块；
- 让物块或料盘出画面；
- 把物块放到料盘边框上；
- 让侧视被支架、线缆或其他物体遮住；
- 在同一批中途修改相机设置和灯光。

## 15. 比赛平台正式单物块数量

正式方案每种形状80组，共11种形状：

| 划分 | 每类数量 | 实体 | 每种颜色/每类 | 用途 |
|---|---:|---|---:|---|
| `train` | 50 | A、B | 10 | 训练模型 |
| `probability_calibration` | 15 | A、B | 3 | 概率温度和拒识阈值 |
| `final_holdout` | 15 | 只用C | 3 | 最终验收，禁止调参 |

总数不含空盘：

```text
11 × (50 + 15 + 15) = 880组双视角单物块样本
```

### 15.1 训练集的推荐拆分

每一种比赛颜色、每一种形状：

```text
实体A拍5组 + 实体B拍5组 = 10组
五种颜色 × 10组 = 每类50组
```

因此每个训练批次使用 `--target-per-label 5`。例如红色：

```text
train-A-red-日期：每类5组
train-B-red-日期：每类5组
```

然后对其余四种比赛颜色重复。

### 15.2 概率校准集的推荐拆分

每种颜色每类共3组，并且A、B都必须出现。因为3是奇数，可交替分配：

```text
颜色1：A拍2组，B拍1组
颜色2：A拍1组，B拍2组
颜色3：A拍2组，B拍1组
颜色4：A拍1组，B拍2组
颜色5：A拍2组，B拍1组
```

这些照片应在不同日期或明显不同的布局/照明批次拍摄。校准集不能参与模型训练。

### 15.3 最终留出集

最终留出集只用从未出现在训练和校准中的实体C：

```text
五种颜色 × 每色每类3组 = 每类15组
```

对应命令使用：

```text
--split final_holdout --instance-id C --target-per-label 3
```

最终留出集拍完后不能根据其结果修改模型、融合权重或阈值；否则它不再是最终留出集，必须重新采集新的独立实体和批次。

## 17. 为什么多颜色数据不会导致形状过拟合

多颜色本身不会造成形状过拟合，反而能阻止模型把颜色误当成形状。关键是每一种形状都应均衡出现全部比赛颜色。

危险的数据分布：

```text
三棱柱几乎全是红色
圆柱体几乎全是蓝色
圆锥几乎全是黄色
```

模型可能把红色当成三棱柱证据。

正确的数据分布：

```text
每一种形状都有红、黄、蓝、绿和第五种比赛颜色
每一种颜色也覆盖全部11种形状
```

颜色只写入 `color_id`，形状训练真值仍是 `label_id`。后续颜色识别主要使用俯视 RGB 中已经由深度确定的物体区域，输出独立 `color_id`；侧视颜色可作为诊断，但不产生抓取坐标。

```text
metadata.json       帧ID、时间戳、内参、外参哈希、标签和质量信息
```

`dual-manifest.jsonl` 用于断点续拍和全局数据索引。不要只删除样本文件夹而不处理清单，也不要手工改文件名冒充其他类别。

如果误拍或误标：

1. 记下终端打印的具体样本路径；
2. 再补拍一张正确样本，允许该类别临时超过目标数量；
3. 在人工审查文件中把错误样本设为 `approved=false`；
4. 不要让错误样本进入训练。

## 19. 拍摄多物块场景

单物块完成后，还要拍每盘5–8件的复杂场景。下面示例包含5件物块：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli `
  --config config\dual\temporary.yaml `
  dual-multi-capture `
  --dataset-root data\dual `
  --batch-id multi-development-20260915 `
  --platform-id temporary `
  --scene-split development `
  --composition "三棱柱,四棱柱,五棱锥,圆锥,圆柱" `
  --occlusion light `
  --count 1 `
  --side-camera-index 1 `
  --color-width 1920 --color-height 1080 `
  --depth-width 848 --depth-height 480 --fps 15 `
  --side-width 1280 --side-height 720 --side-fps 30
```

在多物块窗口中：

```text
C 保存
Q 退出
```

`--composition` 必须准确列出盘中5–8件物块的真实形状；同类出现两次就写两次。`--occlusion` 使用：

```text
none   无明显遮挡
light  轻度遮挡
heavy  重度遮挡
```

正式比赛数据目标：

- `development` 30个场景；
- `final_acceptance` 30个场景；
- 两组都覆盖 `none/light/heavy`；
- 每个物体的真实颜色在人工逐物体审查时另外记录；
- 最终验收场景不能用于调参。

临时平台先拍至少15个场景验证流程即可。

## 20. 逐帧人工审查

生成联系表前，需要当前 D435if 的 RGB-D 空盘背景目录或有效 RGB-D 标定文件。不能使用旧 D415 标定代替。

第一次还没有侧视模型时，可以省略 `--side-shape-model`：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli `
  --config config\dual\temporary.yaml `
  dual-review `
  --samples-root data\dual\temporary `
  --output-dir output\dual-review-temporary `
  --platform-id temporary `
  --dual-calibration config\dual\temporary\calibration.json `
  --side-background config\dual\temporary\side-background.png `
  --background-dir <当前D435if的RGB-D空盘背景目录>
```

尖括号内容是占位说明，不能原样复制。若已有当前 D435if 的有效 RGB-D 标定 JSON，可改用：

```text
--rgbd-calibration <当前D435if的RGB-D标定文件>
```

人工必须逐帧查看：

- 俯视 RGB 是否完整、标签是否正确；
- 深度是否有孔洞或错误前景；
- 侧视是否清晰、物块是否完整；
- 投影 ROI 是否对应同一个物块；
- 是否存在阴影、反光、错配和遮挡；
- 多物块是否发生实例合并或拆分；
- `instance_id`、`color_id` 和 `split` 是否正确。

单物块审查记录示例：

```json
{"sample":"temporary/train-A-red-20260915/triangular_prism/sample-0001","approved":true,"true_label":"triangular_prism","roi_ok":true,"association_ok":true,"shadow_ok":true,"depth_ok":true,"instance_split_ok":true,"notes":"无遮挡，红色实体A"}
```

应用审查决定：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli dual-review-apply `
  --samples-root data\dual `
  --reviews data\dual\review-decisions.jsonl `
  --shape-registry config\shapes\competition-11.yaml
```

生成联系表不等于完成审查。只有人工确认并应用记录后，样本才会得到 `human_reviewed=true`；正式训练默认拒绝读取未经人工审查的样本。

## 21. 形状训练与颜色训练的关系

当前先完成形状链路：

1. 俯视 RGB-D 主流程产生实例、深度几何和形状 Top-2；
2. 侧视 RGB 提取侧面轮廓与棱线；
3. 侧视只能在俯视 Top-2 中消歧；
4. 深度或抓取安全失败不能被侧视升级；
5. 高置信冲突直接拒识。

经典侧视形状模型训练命令：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli dual-side-train `
  --samples-root data\dual\competition `
  --side-background config\dual\competition\side-background.png `
  --shape-registry config\shapes\competition-11.yaml `
  --output models\side-geometry.npz `
  --report output\dual-side-training.json
```

该命令默认只读取 `human_reviewed=true` 的样本，并在报告中检查：

- 每类是否达到50/15/15；
- 每个划分是否覆盖五种颜色；
- 训练/校准是否包含A、B两个实体；
- 最终实体C是否与开发实体隔离；
- 是否存在跨划分重复图像。

颜色模型应作为独立任务使用相同数据中的 `color_id`。在颜色训练正式接入前，不能删除或随意填写 `color_id`。颜色模型的训练/校准/最终留出也必须沿用相同划分，不能在全部照片上调颜色阈值后再把同一批照片当最终测试。

### 21.1 第一批训练数据的固定分组回归检查

如果目前只有`split=train`，还没有独立的`probability_calibration`，可以先用下面的诊断工具在每个“批次×形状”组里固定随机留出3组：

```powershell
.\.venv\Scripts\python.exe scripts\train_dual_group_holdout.py `
  --samples-root data\dual\temporary `
  --side-background config\dual\temporary\side-background.png `
  --shape-registry config\shapes\competition-11.yaml `
  --output-dir output\dual-v1-random-holdout `
  --model-output models\experimental\side-geometry-v1-observed.npz `
  --holdout-per-group 3 `
  --seed 20260915
```

该工具不会修改原始样本、`split`或人工审查状态。固定种子保证重复执行仍使用相同留出样本，并生成逐样本预测和36张联系表。它仅用于检查训练程序和发现明显数据问题，不能代替独立实体C最终留出；若缺少11类中的任何类别，输出模型会绑定已观察子注册表并以非零状态退出，禁止复制到正式的`models\side-geometry.npz`。

## 22. 常见问题

### 22.1 只有左边一个巨大画面

这是基础 `dual-capture` 预览把两张高分辨率图横向拼接后超过屏幕宽度，不代表侧相机没有采集。单物块正式拍摄请使用 `scripts/dual_rgbd_side_capture.py`，它会把三路画面缩放到同一个窗口。

### 22.2 画面一直显示 `WAIT`

看窗口底部的拒绝原因：

| 原因 | 处理方法 |
|---|---|
| `camera_or_object_moving` | 移开手，等待物块和支架稳定 |
| `camera_pair_out_of_sync` | 关闭其他相机软件，检查USB连接和带宽 |
| `primary_rgb_depth_out_of_sync` | 重启程序，检查RealSense流是否稳定 |
| `depth_valid_ratio_low` | 改善距离、角度和照明，检查深度画面 |
| `side_image_blurred` | 清洁镜头、增加光照、检查焦距和相机抖动 |
| `side_camera_missing` | 检查索引、USB口和设备占用 |

不要用 `F` 掩盖持续存在的问题。

### 22.3 侧视黑屏或出现错误相机

关闭所有可能占用摄像头的软件，然后只修改：

```text
--side-camera-index 0
--side-camera-index 1
--side-camera-index 2
```

找到正确侧视相机后，把编号同步写入对应平台 YAML。重新插拔设备后仍需复查。

### 22.4 俯视料盘被截断

优先升高、平移或重新安装俯视相机，让整个料盘完整进入画面并保留余量。不要把降低分辨率当作扩大真实视场的可靠办法。相机移动后必须重做外参和背景。

### 22.5 按空格提示必须先拍空盘

每个新的 `batch-id` 至少要先保存一张 `empty_tray`。切换回编号0拍一张，再进入物块类别。另一个批次生成的 `side-background.png` 不能替代这个批次内空盘门。

### 22.6 拍摄中断了

使用完全相同的命令和 `batch-id` 重新运行。程序会从 `dual-manifest.jsonl` 恢复每类计数。不要更换 `split`、`instance-id` 或 `color-id` 后继续复用旧批次名。

### 22.7 标签选错并已经保存

记录终端打印的样本路径，补拍正确样本，并在人工审查时拒绝错误样本。不要只删除文件夹，因为清单仍可能保留该样本并影响断点计数。

### 22.8 临时平台拍完能否直接训练正式模型

可以用于调试训练程序，但不能作为比赛准确率结论。正式模型必须使用比赛平台重新标定、重新采集并逐帧审查的数据。

## 23. 每批完成后的检查清单

每次退出采集程序后确认：

- [ ] 批次名没有与其他颜色、实体或划分重复；
- [ ] `platform_id` 正确；
- [ ] `split` 正确；
- [ ] `instance_id` 正确；
- [ ] `color_id` 使用统一英文ID；
- [ ] 11种形状真值全部正确；
- [ ] 没有把颜色写进形状标签；
- [ ] 没有连续重复姿态；
- [ ] 没有使用 `F` 强制保存正式数据；
- [ ] 三路画面均完整、清晰、同步；
- [ ] 误拍样本路径已记录；
- [ ] 数据已备份，且没有手工破坏 `dual-manifest.jsonl`。

## 24. 整个项目的推荐执行顺序

```text
临时平台三画面与同步验证
  ↓
临时平台少量单物块/多物块试拍
  ↓
检查目录、标签、投影和联系表
  ↓
搭建比赛刚性平台并锁定五种颜色ID
  ↓
重新标定内参、外参、料盘平面和空盘背景
  ↓
训练集：A/B，50组/类
  ↓
逐帧人工审查
  ↓
概率校准集：A/B，15组/类
  ↓
训练侧视形状模型和融合策略
  ↓
最终留出：新实体C，15组/类
  ↓
多物块开发30盘与最终验收30盘
  ↓
Orin Nano和N100双平台验收
```

只要最终推广门槛没有全部通过，正式运行就继续使用稳定的俯视 RGB-D 单目链路；双视角保留诊断输出，不强制参与抓取。
