# 原始数据、应用结果与逐样本视觉审查

更新：2026-10-02。生成图表不等于完成审查；必须实际打开原图／深度／叠加并记录样本范围和发现。对称、遮挡或无法确认的结构明确保留不确定。

## 1. 分开三种检查

| 层级 | 检查什么 |
|---|---|
| 原始采集 | 配对、图深、深度孔洞、光照、标签与实物 |
| 应用结果 | ROI、实例数量、轮廓、颜色／形状、对应、安全状态 |
| 模型评价 | 数据隔离、失败分母、错误接受、覆盖、耗时 |

训练报告不能替代应用审查，正确标签不能替代真实抓取深度。

## 3. 单RGB-D应用回放和联系表

先用同一空盘／标定逐样本检测。一个样本示例：
```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli `
    --config config\d435if-initial.yaml rgbd-detect `
    --frame-dir data\rgbd-new\pilot-20261002\cone\ACTUAL_SAMPLE_ID `
    --background-dir data\rgbd-new\pilot-20261002\empty_tray\ACTUAL_SAMPLE_ID `
    --output-dir output\rgbd-replay-20261002\frame-0001
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli rgbd-review `
    --results-root output\rgbd-replay-20261002 `
    --output-dir output\rgbd-contact-20261002
```

两处ACTUAL_SAMPLE_ID分别替换为空盘与物块实际样本，不一定相同。rgbd-review的输入是已检测结果目录，参数是results-root，不能直接传原始数据目录。

批量回放模板：
```powershell
$backgroundSample = "data\rgbd-new\pilot-20261002\empty_tray\ACTUAL_SAMPLE_ID"
$reviewIndex = 0
Get-ChildItem -LiteralPath data\rgbd-new\pilot-20261002 -Recurse -Filter metadata.json | ForEach-Object {
    $sampleDirectory = $_.Directory.FullName
    if ((Test-Path (Join-Path $sampleDirectory "color.png")) -and (Test-Path (Join-Path $sampleDirectory "depth.npy"))) {
        $reviewIndex += 1
        $reviewOutput = Join-Path "output\rgbd-replay-20261002" ("frame-{0:D4}" -f $reviewIndex)
        .\.venv\Scripts\python.exe `
            -m sorting_vision.cli `
            --config config\d435if-initial.yaml rgbd-detect `
            --frame-dir $sampleDirectory `
            --background-dir $backgroundSample `
            --output-dir $reviewOutput
        if ($LASTEXITCODE -ne 0) { throw "Replay failed: $sampleDirectory" }
    }
}
```

先填真实backgroundSample。失败停止并记录，不静默跳过。不同批次／平台使用各自的空盘。批量完成后再运行上面的rgbd-review。

## 双机原始联系表与写回

不依赖有效标定，先生成原始三联图：
```powershell
.\.venv\Scripts\python.exe `
    -c "from sorting_vision.dual_validation import build_dual_contact_sheets; print(build_dual_contact_sheets('data/dual/temporary/pilot-blue-20261002', 'output/pilot-raw-review-20261002'))"
```

这个API不运行投影，不修改源审查标志。有效标定后的应用审查用dual-review，命令见[采集标定验收](双视角采集标定与验收.md)，会严格检查采集哈希。

实际查看后可创建逐样本JSONL；以下保守模板尚未通过：
```json
{"sample":"cone/sample-0001","true_label":"cone","roi_ok":false,"association_ok":false,"shadow_ok":false,"depth_ok":false,"instance_split_ok":false,"approved":false,"notes":"待实际逐项审查"}
```

sample相对于samples-root。只有确实查看并确认的项才填true；存在问题保留false、写原因。模板不能批量复制为通过。

```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli dual-review-apply `
    --samples-root data\dual\temporary\pilot-blue-20261002 `
    --reviews output\pilot-review-decisions-20261002.jsonl `
    --shape-registry config\shapes\competition-11.yaml
```

此命令修改对应metadata的标签／审查信息，先备份并核对相对路径。全部五项及approved通过才设human_reviewed=true；没有审查的样本不受影响。

多物块还需逐对象objects：object_id、true_label、side_visible_ratio（0–1）、side_occluded、association_ok、notes。对象数、组成与实际scene必须一致。遮挡或无法确认对应部分记录原因，不强行全部通过。

## 4. 每张图检查清单

1. 原RGB／深度／侧RGB是否同一摆放、标签和颜色是否真实。
2. ROI完整，盘沿、手、第二白盘及背景未成为物块。
3. 实例数量正确，明暗面没有误拆，同色接触没有强行分开。
4. 孔洞、反光、阴影、纹理、弱棱和曲面是否被合理保留／拒绝。
5. 候选线／验证线／真实棱证据分层，遮挡部分单列。
6. 对应属于同一对象，歧义和对称角点不强行标真。
7. health、安全状态、selected和抓取面条件合理。
8. 异常帧在报告与评价分母中保留。

## 5. 审查记录模板

```text
平台／批次、配置／标定／模型版本：
实际打开的原图、联系表和frame ID：
每样本真值、ROI、数量、轮廓及颜色：
孔洞、遮挡、反光、纹理与不确定部分：
错误拆分／合并／对应及拒识原因：
安全状态与selected：
明确通过／拒绝／待补拍结论：
审查人／日期、证据文件和哈希：
```

同一物块某部分不可确认时，不把该部分标成真实棱。开发粗标注不等于人工认证三维真值。只保存独立审查记录时，不自动修改源human_reviewed。

## 6. 审查之后

明确的数据清理与重标注有独立记录；备份原来源。训练和阈值改变后重新看结果图，保留前后对照。手册中的软件自检不代替实机审查或机器人验收。
