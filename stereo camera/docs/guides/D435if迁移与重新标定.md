# D435if 迁移与重新标定

项目当前 RGB-D 相机已由 D415 更换为 Intel RealSense D435if。本次代码已把实时来源改为通用 `RealSenseSource`，新增 D435if 设备名、`d435if-` 帧前缀和独立流配置。旧 D415 类、配置、数据和报告继续保留，只用于兼容与历史复现。

## 为什么不能只改相机名称

D435if 使用宽视场全局快门立体深度模组，带 IMU，并在深度镜头前增加 750 nm 近红外通光滤镜；官方给出的深度视场约为 87°×58°，最大深度输出为 1280×720。D415 的深度视场约为 65°×40°。因此换机后托盘在画面中的尺度、边缘位置、深度孔洞、平面误差和模型特征分布都会变化。

当前算法没有使用 D435if 的 IMU，固定俯视安装也不需要用 IMU 替代相机到机器人外参。官方规格见 [D435if 产品页](https://www.realsenseai.com/products/d435if/) 和 [D400 系列数据表](https://dev.realsenseai.com/download/42003/)。

## 当前配置

当前入口是 [`config/d435if-initial.yaml`](../../config/d435if-initial.yaml)：

| 项目 | 初始值 | 说明 |
| --- | ---: | --- |
| RGB | 1920×1080 @ 30 FPS | 当前连接的 D435IF 已验证可启动的彩色 profile。 |
| 深度 | 848×480 @ 30 FPS | 当前连接的 D435IF 已验证可启动；运行时对齐到彩色图。 |
| 深度范围 | 280–1500 mm | 280 mm 对应最大深度分辨率下约 28 cm 的官方 Min-Z。 |
| 处理缩放 | 0.75 | 实际 P95 延迟需在当前主机重新测量。 |
| 帧前缀 | `d435if-` | 新采集不会与旧 `d415-` 数据混淆。 |

该文件是“初始配置”，不是“已审配置”。颜色参考、分割、平面和抓取阈值暂时继承安全基线，必须用 D435if 实拍结果复核后再调整。若 1280×720 双路启动失败，先在 RealSense Viewer 确认 USB 3 和可用流；可临时把 RGB/深度同时降为 640×480@30，但一个实验内的训练、验证和测试必须使用一致流配置。

## 第一步：安装与验证取流

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,realsense]"

.\.venv\Scripts\python.exe -m sorting_vision.cli `
  --config config\d435if-initial.yaml camera-record `
  --source realsense --session output\d435if-stream-check `
  --max-frames 30 --headless
```

检查保存的元数据：

- `camera_model` 应为 SDK 返回的 D435if 产品名，或配置回退值 `Intel RealSense D435if`。
- 新帧 ID 应以 `d435if-` 开头。
- RGB 与深度时间差应低于 `rgbd.max_rgb_depth_sync_ms`。
- 对齐后的 `color.png` 与 `depth.npy` 尺寸和内参必须一致。

当前环境未连接相机时，软件测试只能验证配置和接口，不能确认实际 USB 流、曝光或深度质量。

## 第二步：重新拍空托盘和单物体

不要复用 D415 的空托盘、`rgbd-calibration.json` 或相机到机器人矩阵。固定 D435if 的最终高度、角度和焦距后运行：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli `
  --config config\d435if-initial.yaml rgbd-capture-assistant `
  --dataset-root data\rgbd-d435if `
  --batch-id d435if-pilot-01 `
  --target-per-label 30 --auto-advance
```

每个批次先拍空托盘，再拍所有类别。完整操作见 [D435if 数据集拍摄助手](D435if数据集拍摄助手.md)。至少拍三个相互独立的批次；不要把同一摆放的连续帧拆到训练和测试两侧。

拍完先审计：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli rgbd-dataset-audit `
  --data-root data\rgbd-d435if `
  --output-report output\d435if-dataset-audit.json
```

还必须实际查看 RGB、深度预览、托盘 ROI、实例掩膜和面拓扑，重点确认宽视场没有把托盘外桌面并入 ROI。

## 第三步：重新生成标定

用当前安装位置下的空托盘生成算法标定：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli `
  --config config\d435if-initial.yaml rgbd-calibrate `
  --background-dir "data\rgbd-d435if\d435if-pilot-01\empty_tray\<样本ID>" `
  --output output\d435if-rgbd-calibration.json
```

省略 `--camera-to-robot` 时保存的是单位外参，只能离线测试。机械臂执行前必须重新标定 D435if 到机器人坐标系的 4×4 变换；D415 的外参不能沿用。

## 第四步：把旧 v4 作为迁移基线

原模型 [`geometry-rgbd-multipose-v4.npz`](../../models/stable/rgbd/geometry-rgbd-multipose-v4.npz) 来自 D415 数据。它可以帮助发现换机域差异，但不能因目录名是 `stable` 就被视为 D435if 已验证模型。

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli `
  --config config\d435if-initial.yaml rgbd-detect `
  --frame-dir "data\rgbd-d435if\d435if-pilot-01\triangular_prism\<物体样本ID>" `
  --background-dir "data\rgbd-d435if\d435if-pilot-01\empty_tray\<空托盘样本ID>" `
  --rgbd-shape-model models\stable\rgbd\geometry-rgbd-multipose-v4.npz `
  --output-dir output\d435if-v4-baseline
```

输出只用于离线对照。框色表示安全状态，不是分类真值；判读方法见 [RGB-D 结果颜色与字段说明](RGB-D结果颜色与字段说明.md)。

## 第五步：训练 D435if 候选

先只使用干净单物体批次，输出到实验目录：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli `
  --config config\d435if-initial.yaml geometry-rgbd-train `
  --data-root data\rgbd-d435if `
  --batch-id d435if-pilot-01 --batch-id d435if-pilot-02 `
  --strict-single-object `
  --output models\experimental\rgbd\geometry-rgbd-d435if-v1.npz `
  --output-report output\d435if-v1-training.json
```

保留 `d435if-pilot-03` 作为批次隔离测试。不要使用 `--base-model` 直接把 D415 exemplars 混入第一版 D435if 模型；先比较纯 D435if 候选，才能判断换机和新数据各自的影响。

## 第六步：多物体和视觉复审

使用 [D435if 多物体批量测试拍摄](D435if多物体批量测试拍摄.md) 采集新组成场景，并为基线和候选分别生成独立输出目录。随后运行：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli rgbd-review `
  --results-root output\d435if-candidate-replay `
  --output-dir output\d435if-candidate-review
```

必须逐帧检查 ROI、数量、粘连/拆分、深度孔洞、类别、吸附点和 `health`。旧 D415 的 47/55、12/31、26/31 等指标不得写成 D435if 结果。

## 推广前条件

D435if 模型进入 `models/stable/rgbd/` 前至少需要：

- 三个独立单物体批次的批次隔离评估，并报告每类召回和 `unknown`。
- 新 D435if 多物体场景的数量匹配、组成匹配和逐帧视觉审查。
- 当前主机预热后的整帧 P50/P95。
- 托盘平面漂移、RGB-D 不同步、深度缺失、遮挡和无吸附面的安全回归。
- 重新测量相机到机器人外参及抓取位置/法向误差。
- 全量 pytest、`compileall` 和 `git diff --check` 通过。

在这些条件满足前，D435if 输出只用于采集、调试和离线识别，不执行真实抓取。
