# D435if多物体场景采集教程

更新：2026-10-02。先让单物块质量和标定通过，再验证整盘。真实接触、遮挡与多个同色物块需要独立场景数据。

## 1. 一台RealSense的场景助手

准备真实组成，示例为4件；只输入实际盘中的物块：
```powershell
Set-Location "C:\Users\d114\Desktop\tech_\stereo camera"
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli `
    --config config\d435if-initial.yaml rgbd-multi-capture `
    --dataset-root data\rgbd-multi-new `
    --batch-id scenes-20261002 `
    --composition "三棱柱:2,四棱锥:1,圆锥:1" `
    --captures-per-scene 5 `
    --interval-ms 500
```

程序显示RGB／深度及质量。空格保存一组；B开始当前场景自动批次，P暂停，N进入新布局，F强制诊断保存，Q退出。进入新布局后必须真实移动物块。

scene-index=0会恢复当前未完成布局；换composition需检查已有scene记录，不能把同一场景目录的真值改成另一组物块。

## 2. 输出与标注边界

保存RGB-D帧、scene.json及场景清单，组成包含label_id和count、场景号、序号及质量。它说明“有哪些物块”，不提供每件实例bbox／mask／棱线真值，不能直接当成监督分割训练集。

同布局5张用于时序／采集稳定检查，不能当5个独立姿态或拆到训练／测试。

## 双机5–8件场景

实际准备5件物块：
```powershell
.\.venv\Scripts\python.exe `
    -m sorting_vision.cli `
    --config config\dual\temporary.yaml dual-multi-capture `
    --dataset-root data\dual `
    --batch-id multi-dev-20261002 `
    --platform-id temporary `
    --scene-split development `
    --composition "triangular_prism,quadrangular_prism,pentagonal_pyramid,cone,cylinder" `
    --occlusion none `
    --count 5 `
    --side-camera-index 1
```

按提示空格保存；Q退出。count为同布局保存次数，不自动变成独立场景。occlusion可选none／light／heavy，final_acceptance用另一批次。若没有圆柱，把组成改成真实启用类别，仍保持5–8件。composition是实际逐件列表，允许重复类别，与单机“类别:数量”的输入格式不同。

## 3. 必须覆盖的布局

- 分离、不同间距、靠盘边、不同朝向。
- 同色接触、异色邻接。
- 主视清晰而辅助视角遮挡／重叠（双机时）。
- 暗面、反光、阴影、深度孔洞。
- 遮挡等级及不确定／无法确认对应部分单列。

固定一组开发布局和另一组冻结验收布局。记录每个真实对象的标签与可见情况；不能用模型预测代替真值。

## 4. 采集后审查

单相机帧先逐组rgbd-detect回放，再rgbd-review生成联系表，见[视觉审查](视觉审查流程.md)。双机使用配套审查入口。统计数量、漏检、误拆／合并、类别、拒识、抓取面和安全状态，失败保留。

## 5. 实时性与停止条件

headless／auto-start会自动采集，应先预览取景并设max-captures限制测试规模。物块／手运动未稳、深度不足、配对异常时先处理质量。强制保存只用于诊断，不计合格采集。
