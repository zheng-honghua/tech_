# 联合三维拓扑与应用链审查（2026-09-17）

## 已实现的链路

俯视RGB-D实例分割和点云 → 主模型类别分数/Top-2 → 外参投影侧视实例 → 侧视LSD → 联合三维证据图 → 跨视角RTrees → 质量自适应Top-2后融合 → 原RGB-D抓取与安全状态 → schema v2目标输出。

`joint_topology.py`对有实测深度的可见面做确定性RANSAC拟合，只有同时被两面附近实际点支持的交边才进入图。侧视线仅在投影点具有足够沿线覆盖、三维线性及低残差时拟合三维边，与已有边按三维共线/重叠匹配。节点、边、拟合面、来源、支持点数和残差保留在`diagnostics.dual_view.cross_view_topology.joint_topology_graph`。

联合图的12个尺度归一化统计进入跨视角模型，特征版本4；独立侧视模型仍为特征版本3。运行时独立侧视预测额外记录到`independent_side`，不重复投票：跨视角模型已包含同一侧视RGB特征。俯视类别概率与跨视角概率分别温度校准，再按侧视质量、类别对可靠性、俯视拓扑质量加权，只能消歧俯视Top-2。

图为**部分可见表面证据图**，不是完整闭合多面体。平面交边和三维线端点是由实测点拟合的估计，不是逐点真实顶点标注。侧视图像没有唯一深度时仅记录`NO_RELIABLE_METRIC_LINE_SUPPORT`，不补造隐藏边/隐藏面，不输出独立侧视抓取坐标。节点度与循环秩不得当作完整物体棱数或闭合网格Euler验收。

## 应用层回放

`scripts/replay_dual_application.py`加载同一批留出原始RGB、深度、侧视RGB和双路主机时间戳，通过实际`VisionPipeline3D.process_pair`回放；每组先运行单目获得安全状态，再运行双视角核对非法升级。保存完整schema v2对象、健康信息、配对时差、颜色/形状、抓取状态、冷启动目标选择和标注图。

每张是独立摆放，所以逐张重置跟踪；不重复同一张图片假装机械停稳连续帧。冷启动`selected=false`不等于分类失败，不能据此声称实机无法选择目标。回放不包含相机采集、机器人运动、控制端通信或硬件部署延迟，也不会启动机械运动。

## 使用

新配置单独保存为`config/dual/temporary-joint10.yaml`，不替换v3回退配置或比赛配置。新模型整包为：

- `models/experimental/top-rgbd-joint-v4-observed.npz`
- `models/experimental/side-geometry-joint-v4-observed.npz`
- `models/experimental/joint-topology-dual-v4-observed.npz`
- `models/experimental/dual-fusion-joint-v4-observed.json`

在`stereo camera`目录运行：

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli `
  --config config\dual\temporary-joint10.yaml camera-live `
  --source dual --platform-id temporary `
  --background-dir data\rgbd-background `
```

## 已知接口差异与优化方向

离线训练目前使用整幅侧视图分割，运行使用投影多边形限制的侧视掩膜；质量计算也不同。离线主模型直接分类特征，应用还通过单目混合几何规则、颜色、抓取与健康门。因此分类回归不等于实际应用正确率，必须分别记录。下一步优先统一训练/推理实例掩膜和质量定义，而不是继续增大侧视权重。

图支持依赖俯视已经看到的深度：遮挡导致的完全不可见侧面仍无法被RGB单独恢复。深度片段只覆盖一个面的情况、临时外参错位和背景假棱仍可能限制图质量。需新增实拍拓扑审查数据验证，不能仅凭训练集生成完整几何体。

新模型分支改善4.63个百分点，但最终融合可靠性退化，**不替换v3、不推广**。策略校准选择`log_product`、侧视基础权重0.35、温度0.47742、俯视温度0.61557、最高概率门0.80；实际侧视权重仍乘质量。该选择不是三模型简单平均，也不是端到端联合网络。

三维边中位数1，所有108组只有3条边同时拥有顶视交面与侧视支持来源；未解析侧视线比例中位数为1.0。图已实现跨视角对应和部分证据联动，但数据不足以稳定恢复丰富的顶点/边/面连接，不能称为完备重建。

顶视特征最大变化0.014252出现在红色`pentagonal_prism/sample-0010`的`rgb_edge_support`，其他模型输入不能宣称逐位一致；聚合原始准确率相同不等于每张顶视预测相同。新融合相对俯视纠正6张、改坏2张，变化包含图特征、模型重新训练与概率策略重校准，不是纯图特征单变量消融。

分类阶段错误接受：蓝色`cone/sample-0007`、红色`hexagonal_pyramid/sample-0009`、黄色`hexagonal_pyramid/sample-0015`，均错成五棱锥。它们不是机械执行记录。

## 分类图实际视觉审查

实际查看6张总览，覆盖001—036全部108组RGB/深度/侧视。大多数轮廓和绿线贴合侧视物块，但小RGB框仍覆盖局部面；012第三行、017前两行、024后两行错误支撑仍被低空间质量挡住。026第一行包围体过大，028第三行顶视局部框仍对应低空间质量。联合图没有解决这些分割问题。

020第二行红色六棱锥、030第三行黄色六棱锥仍无法稳定区分五/六棱；001第三行圆锥侧视轮廓合理，但顶视局部面证据导致错候选。深度边缘孔洞及对齐块状采样仍存在，未补造深度。分类联系表是离线分割结果，运行链图片必须单独审查。

## 实际应用链结果：标定域不一致，不能上线

108组冷启动回放共266个分割对象，全部双视角状态为`CALIBRATION_INVALID`，图评估次数0；没有可执行选择，也没有非法安全升级。**这不是融合正确率100%，而是侧视没有进入运行链。**主结果形状含未知准确率47.22%，颜色按原始元数据字符串比较仅1.85%（蓝色元数据拼成`bule`，此数包含标签拼写问题，不能作为正式颜色模型验收）。处理时间P95约1087ms，不包括相机采集、机械停止或通信。

相机坐标域差异已确认：采集和固定AprilTag参考的SDK内参为`fx=1368.4271, fy=1368.4644, cx=973.4771, cy=568.7831`；外参所用棋盘格内参为`fx=1334.0282, fy=1334.6242, cx=965.0440, cy=563.8307`。焦距相对差约2.58%/2.54%，主点差8.43/4.95px，超过当前2%/3px门。采集标定哈希一致108组，但哈希一致不证明SDK点云坐标与RGB标定射线模型一致。

不得直接把外参文件的焦距改为SDK数字，或把内参门放宽：外参和料盘平面解算都依赖此前射线模型，需要使用与保存深度匹配的主相机模型重新解算并检验。旧采集元数据没有完整畸变模型/系数；本次只读SDK设备查询返回`devices=0`，无法读取对应相机的真实参数。未猜测零畸变，未覆盖原标定、未声称标定已修复。新JSON诊断添加`primary_intrinsics_comparison`，便于定位差异。补充诊断后双视角22项测试通过。

实际打开6张应用总览覆盖18张联系表、108组回放，另含全部RGB/深度/侧视：第一组圆锥被拆为多片；绿色、红色棱锥稳定面也有拆片，产生`OCCLUDED`、`UNCERTAIN`和部分`DEPTH_INVALID`；深色物块的LAB原型颜色误判仍明显。由于侧视被标定门挡住，应用图无紫色联合图边是预期结果，不是图渲染已证实通过。
