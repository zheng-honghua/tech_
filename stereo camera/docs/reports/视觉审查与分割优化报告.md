# 视觉审查与分割优化报告

## 审查范围

- 数据：`data/rgbd-multi-scenes/multi-02`、`multi-03`，共20帧。
- 原结果：`output/hexagonal-optimization/final-v4`。
- 修正结果：`output/visual-review-optimization-v1`。
- 审查材料：修正结果对应的 RGB 标注总览、深度总览和 `review-manifest.json`。

本次不仅检查统计值，还逐格查看了 RGB 托盘 ROI、物块框、深度区域，并单独放大异常帧。

## 视觉发现与修改

原结果在 `multi-03/frame-06` 把左上方同一个青色物块的两个可见面拆成两个候选，因此该帧出现5个候选，而实物只有4件。原因是斜面局部低于前景高度门限，形成两个相距很近的深度连通域。

分割器现增加保守的碎片合并：只合并面积明显不对称、间距很小、投影方向重叠、色相接近且高度范围相交的连通域。面积相近的相邻物块不会走此规则。修改后 `multi-03/frame-06` 恢复为一个完整框，两个批次共20帧均得到与场景标注一致的目标数：`multi-02` 每帧3件，`multi-03` 每帧4件，共70个候选。

## 复审结论

- 通过：20帧的托盘 ROI 均限制在白色托盘内部及边缘；托盘外摆放的物块没有进入候选。
- 通过：`multi-03/frame-06` 的重复拆分已消除，修正后未观察到新的错误合并。
- 通过：RGB 检测框与深度中的物块位置一致。
- 保留安全拒绝：本次使用的空托盘参考下，`multi-02/frame-03` 和 `frame-05` 的托盘平面偏移超过3 mm，结果保持 `DEPTH_INVALID`，不得下发抓取。
- 待继续改进：20帧共有7个形状结果被拒识为 `unknown`；这属于分类问题，不能通过放宽分割或安全阈值掩盖。

本次视觉审查结论为：**分割修正接受，分类准确率仍需使用新的独立姿态数据继续训练与验证。**

## 复现命令

```powershell
.\.venv\Scripts\python.exe -m sorting_vision.cli rgbd-review `
  --results-root "output\visual-review-optimization-v1" `
  --output-dir "output\visual-review-optimization-v1-review"
```

以后每次数据、模型或视觉算法变化，都必须重新生成总览、实际查看异常帧并新增或更新对应 Markdown 报告。
